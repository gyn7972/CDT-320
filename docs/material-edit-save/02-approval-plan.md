# Material 변경의 시퀀스 영향 승인안

상태: 사용자 요구에 따라 수정안 재검토 중. 이전 승인 질문에 대한 답변은 승인이 아니라 기존 수동 변경 기능을 보존하라는 요구이므로, 이 문서는 승인 기록이 아니다.

최우선 기준: GUI에서 GOOD/WAIT/NG/SKIP/FLYING, 매핑, Clear를 수행한 결과가 다음 운전에 반영되어야 한다. 실장비에서 이미 사용하는 정상 동작을 유지한다. [기존 경로 분석](03-manual-state-flow.md)을 기준으로 일반 편집과 명시적인 실물 복구를 구분한다.

## 1. Input 재매핑

대상: Sequencing/InputStage/InputStageDieMapApplyService.cs 및 필요한 Material 서비스 연결.

현재: 같은 물리 Die ID를 다시 얻어 Output 소속·픽업·검사 이력을 초기화한다. Output 슬롯은 이전 Die를 참조하여 저장이 실패한다.

제안: 현재 Wafer와 세대를 확인한 뒤 일관된 Material 변경으로 적용한다. 일반 재매핑에서는 현재 Material의 정상 상태와 Output 연결을 함께 취급하고 한쪽 부모만 초기화하지 않는다. 입력에 남은 Die의 새 맵을 갱신한다. GUI의 명시적인 WAIT 재픽업 복구는 기존대로 Pick/검사 이력과 Output 점유를 함께 해제하여 다시 처리할 수 있게 한다. WAIT 복구가 이미 완료된 Die를 과거 이력으로 되돌리지 않는다. 모호한 실물 위치나 손상된 부모 연결은 자동 추정하지 않고 구체적인 복구 사유를 반환한다.

영향: 의도하지 않은 이력 초기화를 방지하면서 명시적인 재픽업 기능을 유지한다. 일반 재매핑 자체를 전체 재처리 용도로 사용하는 경우에는 작업자 의도와 실물 확인 절차를 먼저 확인한다. 축 이동·속도·센서·충돌 인터락은 변경하지 않는다. 실제 시퀀스의 픽업 대상 선택에 영향을 주므로 적용 전 승인이 필요하다.

## 2. Output 상태 편집

대상: Ui/Pages/Work/OutputStageMapTransferPage.cs 및 MaterialStateService의 일괄 상태 편집 메서드.

현재: SKIP에서 DieUid만 지워 SourceDieUid·PlacementUid와 불일치하며, 여러 Die 변경 중간 상태를 저장 worker가 읽을 수 있다.

제안: 선택 대상을 사전 검증하고 동일한 상태 잠금에서 한 번에 반영한다. GOOD/NG 완료, SKIP 제외, 빈 슬롯 WAIT 재대기라는 기존 의미와 다음 배치 대상 반영을 유지한다. 실제 배치한 Die의 DieUid/SourceDieUid/PlacementUid는 서로 일치하도록 함께 관리하고 하나만 지우지 않는다. 기존 사용자 확인과 운전 중 편집 보호를 유지한다.

확인 중인 범위: Output에서 이미 배치된 Die를 작업자가 제거한 후 WAIT로 바꾸어 재배치시키는 사용까지 포함하는지 질문했다. 현재 Output WAIT는 점유 UID를 남기며 Input WAIT의 명시적 복구와 다르다. 이 답변을 받기 전에는 Output의 점유 해제/보존 정책을 새로 구현하지 않는다. 해당 용도가 필요하면 선택 슬롯의 연결을 완전하게 해제하는 확인 절차와 재배치 동작을 구체화해 승인받는다.

영향: SKIP 편집 후 저장 실패를 방지하며, 배치된 슬롯을 빈 슬롯으로 잘못 선택하지 않는다. 작업 대상의 의미에 영향을 주므로 적용 전 승인이 필요하다.

추가 경계: 부분 배치된 Output의 모든 슬롯이 SKIP이면 현재 대상 수 0을 기존 총수량 fallback으로 처리하여 제외 슬롯이 다시 예약될 수 있다. 전체 제외 시 빈맵의 기존 순서로 임의 예약하지 않도록 다음 대상/완료 계산을 일치시켜야 한다. 전체 제외 후 Bin을 완료 처리할지 대기할지는 기존 운전 계약과 사용 의도를 확인하여 승인 범위를 확정한다.

## 3. Input Clear 역참조 보존

대상: Equipment/Materials/MaterialStateService.Clear.cs.

현재: Die의 Output parent 필드만 보고 삭제·보존을 판단하여, Output 슬롯의 잔류 참조를 놓칠 수 있다.

제안: Output 슬롯과 Wafer의 역참조를 함께 확인한다. 정상 Output 이력을 보존하며, 부모 정보와 역참조가 모순되면 삭제 전 구체적인 복구 사유를 반환해 부분 삭제를 방지한다. 불명확한 자재 위치를 임의로 정상 처리하지 않는다.

영향: 손상 상태에서 Clear가 추가 손상을 만들지 않는다. 기존 센서 검사와 완료 조건을 유지한다.

## 검증

GOOD/WAIT/NG/SKIP/FLYING 각각의 UI→Material→저장/재로드→다음 후보를 검증한다. Input의 GOOD/NG/SKIP→WAIT와 실제 복귀 확인 후 WAIT 재픽업, 일반 재매핑 전후 물리 Die 식별자·Output 연결·잔여 픽업 대상, 97개 SKIP 일괄 편집 후 저장, 정상/손상 역참조 Clear를 장비 연결 없이 시험한다. 일부 변경 실패나 저장 실패를 전체 성공으로 표시하지 않아야 한다.

실장비 운전·배포는 승인 범위에 포함하지 않는다. 운전 중 Recipe 적용 정책, 승인 목록 밖 신규 WAIT, 부분 작업 후 순서 재편성 등 현재 시퀀스 정책 변경은 별도 분석·승인 대상으로 남긴다.
