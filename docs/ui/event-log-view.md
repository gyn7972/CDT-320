# EventLogPage 조회 모드와 표시 캐시

## 적용 범위

EventLogPage를 사용하는 이벤트·경고·데이터·작업·Input/Output/Front/Rear 시퀀스 이력 화면에 적용한다. 별도 AlarmHistoryPage는 대상이 아니다. 시퀀스 이력이라는 이름은 표시할 로그 종류를 뜻하며, 시퀀스 동작을 변경하지 않는다.

이 변경은 화면의 조회·표시만 담당한다. EventLogger의 기록 정책, CSV 형식, 장비 동작, 인터락은 변경하지 않는다.

## 사용 방법

| 동작 | 데이터 출처 | 새 로그 반영 |
| --- | --- | --- |
| 최초 진입 / **실시간** 버튼 | 현재 프로그램의 오늘 로그 메모리 | 화면이 보이는 동안 갱신 |
| 날짜 선택 / **REFRESH** | 선택 날짜의 CSV 조회 결과 | 실시간 행을 섞지 않음 |
| **OPEN FILE** | 사용자가 선택한 CSV 조회 결과 | 실시간 행을 섞지 않음 |

- 제목에 `실시간 (오늘)`, `파일 조회` 또는 파일명을 표시한다. 탭 재진입과 번역 재적용 후에도 현재 모드를 유지한다.
- 파일 모드에서 날짜·표시 상한·최근 1시간 조건을 바꾸거나 페이지에 재진입하면 다시 조회한다. REFRESH는 직접 연 파일이 있으면 그 파일을 다시 읽는다.
- **실시간** 버튼은 직접 연 파일을 해제하고 날짜를 오늘로 맞춘다. 실시간 상태에서 자정이 지나면 오늘 날짜로 갱신한다.
- 직접 연 파일은 DATE 선택값으로 거르지 않는다. 최근 1시간 및 텍스트 조건은 적용한다.
- 파일의 최근 1시간 조건은 조회 시작 시각을 기준으로 고정한다. 실시간은 현재 시각을 기준으로 만료 행을 약 1초 간격으로 제외한다.
- 검색은 현재 캐시의 최신 N개 안에서만 수행한다. 표시 상한은 500 / 2000 / ALL이며, ALL도 안전 상한 10,000개다.

실시간 메모리는 재시작 전 이력을 포함하지 않고, 기록 정책에 따라 CSV와 행 수가 다를 수 있다. 재시작 전 기록은 파일 조회로 확인한다. 기존 날짜별 읽기 API는 해당 날짜 기본 CSV만 읽으므로 회전된 보관 파일은 OPEN FILE로 선택한다.

## 수정할 파일

| 파일 | 책임 |
| --- | --- |
| `QMC.CDT-320/Ui/Pages/History/EventLogPage.Designer.cs` | 정적 컨트롤·배치·색·크기·선택 목록·컨트롤 이벤트 연결 |
| `QMC.CDT-320/Ui/Pages/History/EventLogPage.cs` | 조회 모드 전환, 비동기 파일 읽기, 구독 수명, 그리드 표시 |
| `QMC.CDT-320/Ui/Common/History/EventLogDisplayBuffer.cs` | 화면 전용 행 캐시, 동일 참조 중복 제외, 개수·날짜·시간 범위 제한 |

공통 캐시는 WinForms 컨트롤·설정·파일·장비에 접근하지 않는다. 기존 제목/필터/그리드 구조는 유지하며, 필터 TableLayoutPanel의 마지막 빈 열에 실시간 버튼을 배치했다. 이 열의 폭만 확보하므로 가변 검색 입력 폭은 줄어든다. Designer에는 컨트롤 생성용 별도 함수를 호출하지 않는다.

## 조회 흐름과 안전 장치

1. 날짜·조회 모드가 바뀌면 이전 캐시와 대기 행을 즉시 비우고 요청 번호를 올린다.
2. 파일 읽기는 백그라운드에서 한 번에 하나만 실행한다. 연속 요청은 마지막 조건으로 합친다.
3. 완료 시 요청 번호와 화면 수명을 확인한다. 전환·숨김·Dispose 후 늦게 도착한 결과는 표시하지 않는다.
4. 실시간은 먼저 구독하고 메모리를 읽는다. 조회와 알림에 함께 포함된 **동일 EventRow 객체**만 중복에서 제외한다.
5. 로그 콜백은 날짜·종류 판정과 제한된 큐 추가만 수행한다. 컨트롤 접근과 번역·그리드 생성은 UI 타이머에서 처리한다.
6. 타이머는 250ms 간격에 최대 100행을 반영한다. 대기 1,000행을 넘으면 다음 갱신에서 최근 메모리로 다시 맞춘다. 이는 최신 범위 표시 정책이며 모든 발생 로그를 계속 보존하는 기능은 아니다.
7. 파일 모드·숨김·Dispose 시 라이브 구독과 타이머를 중단한다. 이력 표시 설정이 꺼지면 캐시를 비우고 안내 상태로 전환한다.

CSV에는 이벤트 고유 식별자가 없다. 따라서 시간·문구가 같다는 이유로 파일과 실시간 행을 합치거나 제거하지 않는다. 같은 내용으로 별도 발생한 로그는 유지한다. 메모리 스냅샷에서 표시 상한으로 잘린 참조도 기억하여, 늦은 알림이 최신 행을 밀어내지 않도록 한다.

## 검증과 남은 확인

장비를 실행하지 않고, 별도 OutDir의 솔루션 Build와 생산 소스를 직접 컴파일한 격리 테스트로 검증한다. 격리 테스트는 설정·기록기·페이지 베이스를 테스트 대체 클래스로 연결하며, 장비 어셈블리와 운영 CSV를 사용하지 않는다.

2026-09-06 검증 결과: 별도 출력 솔루션 Build 오류 0개/기존 경고 41개, 격리 검사 58개 통과. 날짜 캐시 초기화, 동일 참조 중복, 정상 반복 보존, 파일/실시간 전환, 늦은 파일 완료·숨김·Dispose·설정 OFF, 1,100행 폭주 후 최신 500행 복원, 시간 만료, 번역 후 모드 제목, Designer 이벤트의 외부 접근 차단을 확인했다. 변경 대상의 `git diff --check`도 통과했다.

현장/시뮬레이터 확인 항목:

- Designer에서 버튼·목록·TableLayoutPanel을 직접 선택하고 속성을 수정할 수 있는지
- 장비 화면 해상도/DPI에서 검색 입력과 실시간 버튼이 잘리지 않는지
- 날짜를 바꾼 뒤 검색해도 이전 날짜 캐시가 다시 나타나지 않는지
- 파일 읽기 중 실시간 전환·다른 화면 이동 후 이전 결과가 끼어들지 않는지
- REFRESH에는 라이브가 섞이지 않고, 실시간 버튼은 오늘의 새 로그를 반영하는지
- 탭 재진입·언어 변경 후 제목의 모드 표시가 유지되는지
- 실제 로그량과 10,000행 검색에서 입력 응답성과 시퀀스 주기에 영향이 없는지

실제 Visual Studio Designer, 실제 CSV 읽기, 운전 중 성능은 격리 테스트만으로 보증하지 않는다. 기존 EventLogger 읽기 API는 일부 파일 오류를 빈 결과로 반환하므로, 화면이 모든 파일 오류와 정상 0건을 구별하지는 못한다. 대량 검색의 지연 실행·추가 성능 개선 및 공통 S/M/L 스타일 적용은 별도 후속 단계다.
