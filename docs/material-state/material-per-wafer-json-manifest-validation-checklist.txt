CDT-320 Material Per-Wafer JSON + Manifest 검증 체크리스트

문서 목적

이 체크리스트는 Material 저장 구조를 Wafer별 JSON + 고정 세대 Manifest로 변경할 때
다음 두 목표를 객관적 증거로 검증하기 위한 문서다.

1. 생산 Wafer 누적에 따라 hot save의 실제 disk write byte가 계속 증가하지 않는다.
2. 프로그램 재시작 후 Material 상태가 마지막 정상 commit과 의미적으로 동일하다.

Auto Sequence, Interlock, Motion, Vision, Material 비즈니스 전이는 수정하지 않는다.
저장 원자성이나 성능을 증명할 수 없으면 금지 영역을 수정해 우회하지 말고
FAIL 또는 BLOCKED로 남긴다.


0. 사용 규칙

체크 상태:

[ ] 미검증
[x] 검증 완료

판정 값:

- PASS
- FAIL
- BLOCKED
- NOT RUN
- N/A

중요:

- 체크 표시만으로 PASS 처리하지 않는다.
- CODE 검토만으로 runtime, crash, performance, field 항목을 PASS 처리하지 않는다.
- 실행하지 않은 항목은 NOT RUN으로 남긴다.
- 환경 또는 승인 부재로 실행할 수 없으면 BLOCKED와 이유를 기록한다.
- FAIL 항목을 경고로 축소하거나 다음 단계에서 자동 면제하지 않는다.
- Auto Sequence/Interlock diff가 하나라도 있으면 보호 gate는 FAIL이다.
- 혼합 generation 복구가 한 번이라도 발생하면 atomic recovery gate는 FAIL이다.
- 운영 D:\CDT-320 데이터를 수정한 destructive test는 무효다.
