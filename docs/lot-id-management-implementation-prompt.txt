2. 사용자 확정 요구사항 (2026-07-27)

2.1 LOT 단위
- 여러 카세트를 묶어 한 LOT 으로 본다.
- 따라서 입력 카세트 소진(StopAutoSequenceIfInputCassetteComplete)은 LOT 완료가 아니다.
  카세트만 교체하고 같은 LOT 을 이어서 진행할 수 있어야 한다.
- LOT 완료는 작업자가 명시적으로 [LOT 완료] 를 눌렀을 때만 발생한다.

2.2 LOT 없이 자동 운전
- 금지한다. 활성 LOT 이 없으면 자동 운전 START 를 차단한다.
- 임시 LOT 자동 생성도 하지 않는다(사용자 확정: "임시 LOT 생성도 막자").

2.3 입력 방식
- 이번 구현은 수동 입력(Edit 컨트롤)만 만든다.
- 바코드 리더 2대는 현재 wafer ID 전용이므로 LOT ID 입력에 사용하지 않는다.
- 다만 이후 바코드 연동이 가능하도록, LOT ID 확정 경로를 단일 메서드로 만들어 둔다.

2.4 레시피 LotId 필드
- LOT ID 를 입력하면 활성 레시피(RecipeProject.LotId)에도 기록하고 레시피를 저장한다.
- 즉 레시피 LotId 는 "다음 기동 시 기본값" 역할을 유지한다.

4. 구현 대상

4.1 신규: Equipment\Lots\LotSessionService.cs

LOT 시작/완료의 단일 진입점. 아래 두 체계를 하나의 ID 로 묶는 책임을 진다.

  public static bool TryStartLot(Form1 host, string lotId, out string reason)
    - 검증 순서
      1) lotId 공백/null 이면 거부
      2) 이미 활성 LOT 이 있으면 거부(먼저 완료하라고 안내)
      3) host / host.Machine 준비 확인
    - 처리 순서
      1) MaterialStateService.SetProductionLotId(lotId)  ← 4.2 신규 API
      2) 활성 RecipeProject.LotId = lotId, host.SaveMachineRecipe(host.ActiveRecipeName)
      3) LotStorage.OpenLot(lotId, recipeName, totalDies)   ← 동일 ID 사용이 핵심
         totalDies 는 MachineController.ResolveProductionStatsTotalDies() 와 동일 기준
      4) 한글 로그 + EventLogger(EventKind.Event, "LOT", "LOT-START", ...)
    - 실패 시 어떤 것도 반영하지 않는다(부분 적용 금지).

  public static bool TryCompleteLot(Form1 host, out string reason)
    - 활성 LOT 없으면 거부
    - 완료 직전 ProductionStatsSnapshot 을 읽어 Lot 카운터에 반영
      (ProcessedDies / GoodCount / NgCount)
    - LotStorage.CloseLot(aborted: false)  → 내부에서 SaveJson(Log\Lots) 수행
    - 한글 로그 + EventLogger(EventKind.Event, "LOT", "LOT-COMPLETE", ...)

  public static bool IsLotActive { get; }
  public static string ActiveLotId { get; }

  주의: LotStorage.ActiveInputDieMap 은 DieMap 시각화/시퀀스 20여 곳에서 활발히 사용 중이므로
        LotStorage 클래스 자체를 삭제하거나 이름을 바꾸지 않는다.
