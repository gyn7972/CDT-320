## 0. 이 작업의 규칙 (반드시 준수)

1. **시킨 것만 한다.** 아래 "변경 범위" 외에는 손대지 말 것. 걸림돌이 생기면 임의로
   해결하지 말고 **"문제 있다, 어떻게 할까요?"로 팀장님께 물어볼 것**.
2. **시퀀스 코드는 무조건 승인 후 진행.** 편집 전에 변경할 파일·함수·라인 목록을
   팀장님께 전부 고지하고 승인받은 뒤 편집한다.
3. **인터락/가드 코드는 0건 수정.** 이동은 전부 기존 유닛 Avoid 이동 함수 재사용 —
   MotionGuard·축 VerifyMotionGuard·SharedRailX 규칙은 그대로 타야 한다. 가드에
   막혀 실패하면 가드를 고치지 말고 팀장님께 보고.
4. **빌드 주의**: 기본 빌드 출력이 실장비 실행 폴더로 직결된다. 장비 실행 중 기본
   빌드 금지. 검증 빌드는 `/p:OutDir=<임시경로>` 우회.
5. **모션 속도 스케일 규칙**: 신규 이동 명령/속도/가감속 코드를 작성하지 말 것.
   기존 `MoveInputStageAxisAvoidAsync` / `MoveOutputStageAxisAvoidAsync` 경로 그대로
   재사용한다(속도 결정은 유닛/가드 레이어 기존 로직).
6. **계측 필수(§4)**: 동시 시작·join·정리 각 지점에 수치 로그. 실장비 1회 Ready로
   "4축이 언제 출발해 언제 끝났는지" 확정 가능하게.
7. `ActualPosition`이 지령값을 반환하는 것은 의도된 설계다. 교정하지 말 것.
8. 시뮬레이션 모드에서 정상/실패 두 경로 확인 후 실장비.

### 1-2. 순서 제약 조사 결과 (이 불변식들은 변경 후에도 유지해야 한다)

1. **핀 하강은 Step2보다 먼저 완료**되어야 한다 — Step2 피더 자동복구가 스테이지
   위를 통과(Y 이동)하고 ExpanderZ 복구가 스테이지를 움직인다. 핀(니들Z/이젝트핀Z)이
   올라온 채면 파손 위험. → **핀 2축 완료 대기는 Step1에 남긴다.**
2. **PickerX(Step8) 전 InputVisionX Avoid 확정** — 기존 게이트가 검사한다.
   → VisionX join을 Step5 슬롯에서 끝내므로 자동 충족(게이트 무변경).
3. UpperHeadMoveSafetyCheck(Step2)는 니들Z/이젝트핀Z/VisionX 상태를 참조하지 않음
   (확인 완료: InputFeeder/OutputFeeder/ExpanderZ/GoodStageZ만 본다).
4. "픽커 Z/Y 먼저 → VisionX" 순서(21a81831)는 이번에 팀장님 승인으로 폐지.
   비전X는 Ready 시작에 출발하고, 완료 확인만 기존 Step5 자리에서 한다.

## 2. 변경 범위 (이 파일 하나만)

**파일: `QMC.CDT-320\Sequencing\MachineReadySequence.cs`**

### 2-1. Step1 `MoveInputStageNeedleEjectZAvoidAsync` (865~898행) — 4축 동시 시작

현재:

```csharp
int result = await MoveInputStageEjectPinZAvoidAsync(unit, ct).ConfigureAwait(false);
if (result != 0) return result;
result = await MoveInputStageNeedleZAvoidAsync(unit, ct).ConfigureAwait(false);
if (result != 0) return result;
```

변경:

1. **비전X 2축 Task를 가장 먼저 동시 시작**해 인스턴스 필드(예:
   `_readyVisionXAvoidTask`)에 보관한다. 기존 함수 그대로 사용:
   `MoveInputStageVisionXOnlyAvoidAsync(ct)` ∥ `MoveOutputStageVisionXOnlyAvoidAsync(ct)`
   — 두 Task를 하나로 묶어(WhenAll 래핑, 첫 비-0 결과 반환) 보관.
2. 이어서 **이젝트핀Z ∥ 니들Z를 병렬 발행**(`Task.WhenAll`)하고 **이 스텝에서 완료
   대기**한다(§1-2 불변식 1). 둘 중 비-0이 있으면 해당 결과로 실패(기존 알람 코드
   `READY-INPUT-STAGE-EJECT-Z` / `READY-INPUT-STAGE-NEEDLE-Z` 그대로 각 함수가 반환).
3. 스텝 로그 문구를 "니들Z/이젝트핀Z 병렬 + 비전X 동시 시작"으로 갱신(§4-1).
4. InputStageUnit이 null이라 Skip하는 경우에도 비전X Task 시작은 수행할 것
   (OutputStageUnit은 별개 유닛이다 — 기존 Skip 로직 재배치에 주의).

### 2-2. Step5 `MoveInputOutputVisionXOnlyAvoidAsync` (350~384행) — join 스텝으로 변경

현재: Input/Output Task를 생성해 WhenAll.

변경:

1. `_readyVisionXAvoidTask`가 **있으면 새 이동을 발행하지 않고 그 Task를 await**(join)
   한다. 결과 비-0이면 그대로 실패 반환(알람 코드 기존 유지 —
   실패는 각 내부 함수 `READY-INPUT-STAGE-VISION-X-EX`/`READY-OUTPUT-STAGE-VISION-X-EX`
   계열이 이미 만든다).
2. Task가 **없으면(방어)** 기존 로직 그대로 생성+WhenAll — 단독 호출/재진입 안전.
3. join 완료(성공/실패 무관) 후 `_readyVisionXAvoidTask = null` 로 정리.
4. 스텝 이름/ReadyStepId/스텝 수는 **변경하지 않는다**(진행률 UI 무변경). 로그 문구만
   "선행 시작된 VisionX Avoid 완료 확인"으로 갱신(§4-2).

### 2-3. 고아 Task 정리 — `RunAsync` (102~141행)

Step1~4 사이에서 실패/취소로 시퀀스가 중단되면 비전X Task가 고아로 남는다.
`RunAsync`의 반환 경로 전체(스텝 실패 반환, `OperationCanceledException`, 일반
예외, 정상 완료)에서 **보관 Task가 남아 있으면 완료를 관찰하고 정리**하는 헬퍼
(예: `DrainReadyVisionXAvoidTaskAsync(string reason)`)를 호출한다:

- Task가 null이면 무동작.
- 남아 있으면 await로 완료 대기(이동은 Avoid 방향 단순 이동이라 대기가 안전하다.
  유닛 Wait에 자체 타임아웃이 있으므로 무한 대기 없음), 결과/예외를 §4-3 로그로
  남기고 null 정리. 예외는 삼키고 로그만(이미 상위 실패가 주 오류다).
- **`MotionGuardRuntime.BeginManualSequenceProcessMove` using 범위를 벗어나기 전에
  반드시 정리가 끝나야 한다**(가드 스코프 밖에서 카메라가 움직이는 상태 금지) —
  따라서 정리 호출은 using 블록 안(try/finally 권장)에서 한다.

1. **빌드**: `/p:OutDir=<임시경로>` 우회 빌드로 컴파일 확인(기본 빌드 금지).

   시 §4-3 드레인 로그가 남고 unobserved exception이 없는지 확인.
4. **실장비(팀장님 진행)**: Ready 총 소요 전/후 비교(§4-2 elapsedMs), 픽커 Z/Y 이동
