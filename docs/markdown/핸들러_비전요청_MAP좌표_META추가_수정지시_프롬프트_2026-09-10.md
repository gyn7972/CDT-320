# 핸들러 수정 지시 — 비전 검사 요청 META 에 웨이퍼 맵 ROW/COL 추가 (2026-09-10)

## 목적

비전이 저장하는 검사 이미지 파일명·index.csv 에 핸들러 결과 CSV(`AK_DT_*.csv`)와 **같은 값**의
`PICK_WAFER_ROW / PICK_WAFER_COL` 을 찍기 위해, 핸들러가 비전 INSPECT 요청을 보낼 때 그 두 값을 META 로 함께 보낸다.

- 지금 와이어에는 `die_index`(=CHIP_SEQ)와 `gridx;gridy`(=`Wafer_IndexX/Y`, 로컬 0-base)만 실린다.
- CSV 의 ROW/COL 은 `Wafer_OriginalIndexY/X`(맵 원본 좌표)라 비전이 알 수 없다.
- 비전은 이미 준비되어 있다: META 에 `map_row`/`map_col` 이 오면 파일명 `…_R{row}C{col}_…` 과 index.csv 열에 기록하고,
  없으면 기존 형식 그대로 저장한다. **핸들러가 먼저/나중 어느 순서로 배포해도 통신은 깨지지 않는다.**

## 와이어 규격 (변경 후)

기존 8파트·WAFER_ID/RECIPE_ID/LOT_ID 는 그대로 두고, 마지막 META 토큰 끝에 두 키만 추가한다.

```
CAMERA|INSPECT_ASYNC|FINDER|HEAD|HEAD_INDEX|DIE_INDEX|GRIDX|GRIDY|CHANNEL|WAFER_ID|RECIPE_ID|LOT_ID|request_id=…;group_id=…;result_timing=…;operation=…;map_row=23;map_col=18
```

| 키 | 값 | 출처 (CSV 열과 동일 변수) |
|---|---|---|
| `map_row` | 정수 | `ResolveMapIndex(die.Wafer_OriginalIndexY, die.Wafer_IndexY)` = CSV `PICK_WAFER_ROW` |
| `map_col` | 정수 | `ResolveMapIndex(die.Wafer_OriginalIndexX, die.Wafer_IndexX)` = CSV `PICK_WAFER_COL` |

- 값은 숫자만(비전 META 파서는 `|` `;` `=` 및 제어문자를 거부한다). 모르면 키를 생략하거나 `-1`.
- `GRIDX/GRIDY`(로컬 격자)는 **바꾸지 말 것** — 비전 맵 표시·XYT 푸시가 이 값을 쓴다.
- Bin(출력 스테이지 후검사) 요청은 선택 사항: 보내려면 CSV `PLACE_WAFER_ROW/COL` 과 같은 값(`outputMapY/X + 1`)을 같은 키로 보낸다.

## 수정 위치 (CDT-320_New_1차업데이트 기준)

1. `Equipment/Vision/VisionDieAddressStore.cs`
   - `VisionDieAddress` 에 `public int MapRow { get; set; } = -1;`, `public int MapCol { get; set; } = -1;` 추가.
   - `Set(...)` 에 선택 인자 `int mapRow = -1, int mapCol = -1` 추가해 저장.
2. `Sequencing/Picker/PickerBottomAndSideInspectionSequence.cs` `RegisterVisionDieAddress(InspectionTarget target)`
   - `VisionDieAddressStore.Set(fb, target.PickerNo, target.Die.InputSequenceNo, target.Die.Wafer_IndexX, target.Die.Wafer_IndexY, target.Die.DieId, target.Die.WaferID_Input,`
     **`mapRow: ResolveMapIndex(target.Die.Wafer_OriginalIndexY, target.Die.Wafer_IndexY), mapCol: ResolveMapIndex(target.Die.Wafer_OriginalIndexX, target.Die.Wafer_IndexX)`**`)`
   - `ResolveMapIndex` 는 `VisionInspectionResultFileWriter` 의 것과 같은 규칙(`original >= 0 ? original : local`). 공용 위치로 옮기거나 동일 로직을 둔다.
   - 같은 방식으로 `PickerBottomInspectionSequence.cs`(약 1094행) 와 `ColletCalibrationSequence.cs`(약 2084행, die 가 있을 때만) 호출부도 맞춘다.
3. `Equipment/Vision/VisionAdapters.cs` `ResolveDieAddress(...)` / `TryResolveAutoDieAddress(...)`
   - 조회한 `VisionDieAddress.MapRow/MapCol` 을 요청 컨텍스트로 넘긴다.
4. `Equipment/Vision/VisionInspectionProtocol.cs`
   - `VisionInspectionRequestContext` 와 `VisionInspectionEnvelope` 에 `MapRow`, `MapCol`(기본 -1) 추가, 생성자/`ToEnvelope` 에서 전달.
   - `ToWireLine()` 의 META 조립부:
     ```csharp
     string meta = "request_id=" + RequestId + ";group_id=" + GroupId +
                   ";result_timing=" + ResultTiming + ";operation=" + Operation;
     if (MapRow >= 0 && MapCol >= 0)
         meta += ";map_row=" + MapRow.ToString(CultureInfo.InvariantCulture) +
                 ";map_col=" + MapCol.ToString(CultureInfo.InvariantCulture);
     Append(sb, meta);
     ```
   - `Validate()` 에서 META 값에 구분 문자가 없는지 검사하는 기존 규칙(`ContainsWireSeparator`)은 그대로 적용된다.
5. (선택) `Sequencing/OutputStage/OutputPostPlaceInspectionQueue.cs` Bin 요청에도 `receiveTarget.DieMapY + 1`, `DieMapX + 1` 을 같은 키로.

## 검증

- 핸들러 이벤트 CSV 의 VISION 와이어 라인에 `;map_row=…;map_col=…` 이 붙는지 확인.
- 같은 다이의 `AK_DT_*.csv` 행(`PICK_WAFER_ROW/COL`)과 값이 같은지 3건 이상 대조. 예: 2026-09-09 NG CSV CHIP_SEQ 549 → `map_row=23;map_col=18`.
- 비전 배포 후: 저장 파일명 `0549_17_22_R23C18_P4_…png`, 웨이퍼 폴더 `index.csv` 의 `MapRow,MapCol` 열이 채워지는지 확인.
- 비전 미배포 상태에서 핸들러만 먼저 배포해도 비전이 META 미지 키를 무시하므로 검사 동작 영향 없음(비전 `VisionWireProtocol.TryParseMeta` 확인 완료).

## 하지 말 것

- `GRIDX/GRIDY` 를 원본 좌표로 바꾸지 않는다(비전 맵 격자 반전·시프트).
- `DIE_INDEX`(InputSequenceNo) 의미를 바꾸지 않는다(CHIP_SEQ 대조 키).
- 다른 META 키 이름을 쓰지 않는다 — 비전은 정확히 `map_row`, `map_col`(소문자, 언더스코어)만 읽는다.
