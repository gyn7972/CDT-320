## 2. 수정 원리 — 게이트 루프를 FollowMoveAsync 호출 전에 삽입

대상: [PickerPlaceSequence.VisionRetreat.cs](../../QMC.CDT-320/Sequencing/Picker/PickerPlaceSequence.VisionRetreat.cs)
`TryFollowPickerXBehindOutputVisionRetreatAsync` — `TryGetFollowGapParameters` 성공 직후,
타임아웃/속도 해석 **앞**에 삽입(위임 시 속도 해석 낭비 방지).

역할 매핑(원본과 후행/선행이 반대이므로 주의):
| | 원본(코디네이터) | 이식본(Place) |
|---|---|---|
| 후행(출발 대기측) | InputVisionX | **PickerX** |
| 선행(퇴장측) | 픽커X | **OutputVisionX**(회피 상승 중) |

게이트 루프(의사코드 — bound/firstCommand 식은 FollowMoveAsync Phase 1과 동일식, 원본도 동일하게 미러함):
```csharp
// 게이트 거리 = 해당 픽커의 OUTPUT SAFETY OFFSET 설정값(§1). 0 이하면 게이트 비활성(현행 동작).
double gateDistanceMm = GetPlaceFollowStartGateDistanceMm();   // Side에 따라 Front/RearPicker.Setup.OutputSafetyOffset
if (gateDistanceMm > 0.0)
{
double visionStartActual = visionX.ActualPosition;          // 게이트 시작 시점 기준(원본 관례)
DateTime gateBegin = DateTime.UtcNow;
int gateTimeoutMs = MotionSpeedScale.ScaleDefaultTimeoutMs(PlaceFollowStartWaitTimeoutMs); // 규칙 ⑤
bool gateWaitLogged = false;
while (true)
{
    ct.ThrowIfCancellationRequested();

    // 회피 Task가 끝났고 축도 정지면 추종 실익 없음 → 위임(외부 ShouldFollow 판정과 일관)
    if (_outputVisionRetreatMoveTask == null ||
        (_outputVisionRetreatMoveTask.IsCompleted && !visionX.IsMoving))
        { /* Check 로그(§5) */ return -24; }

    double leadingActualNow  = visionX.ActualPosition;
    double trailingActualNow = pickerX.ActualPosition;
    double boundNow = direction > 0 ? leadingActualNow + homeGap - safetyGap
                                    : leadingActualNow - homeGap + safetyGap;
    double firstCommandNow = direction > 0 ? Math.Min(_targetPickerX, boundNow)
                                           : Math.Max(_targetPickerX, boundNow);
    double firstMoveNow = direction > 0 ? firstCommandNow - trailingActualNow
                                        : trailingActualNow - firstCommandNow;
    double leadingDepartureNow = direction > 0 ? leadingActualNow - visionStartActual
                                               : visionStartActual - leadingActualNow;

    if (leadingDepartureNow >= gateDistanceMm &&
        firstMoveNow >= gateDistanceMm)
        { /* Ok 로그(§5, waitedMs 포함) */ break; }

    if (!gateWaitLogged) { /* Wait 로그(§5) 1회 */ gateWaitLogged = true; }

    if ((DateTime.UtcNow - gateBegin).TotalMilliseconds >= gateTimeoutMs)
        { /* Check 로그(§5, 타임아웃) */ return -24; }

    await Task.Delay(PlaceFollowStartPollMs, ct).ConfigureAwait(false);
}
}
// 이하 기존 코드 그대로(타임아웃/속도 해석 → "Place 피커X 팔로잉 진입을 시작합니다" → FollowMoveAsync)
```
두 조건(선행 퇴장·첫 명령 이동량) 모두 같은 설정값 `gateDistanceMm`를 임계로 쓴다(원본은 20/20
동일값 2상수였으므로 구조 동일).

- **-24 반환 = 위임**: 호출자 `MovePlacePickerXEntryByVisionFollowOrFallbackAsync`(R6)는 nonzero면
  `JoinOutputVisionRetreat` 후 일반 이동(공유레일 wait-gate 경유)으로 재시도한다 — 검증된 경로,
  후퇴 없음. -24 값은 코디네이터 위임 코드와 관례 통일(R6은 0 여부만 판단하므로 값 충돌 없음,
  로그 `followResult=-24`로 식별).
- 원본은 타임아웃 고정 1000ms지만 이식본은 **스케일 필수**(저속 스케일에서 비전 20mm 이동
  시간이 늘어나는 만큼 타임아웃도 늘려 오탐 위임 방지 — C2 관례 동일).
- cycle stop: Place 배치 드레인 정책이 상위 스텝에서 처리 — 게이트 자체는 `ct`만 존중한다.
- `pickerX`/`visionX`는 함수 서두에서 이미 BaseAxis로 확보되어 있음(ActualPosition/IsMoving 사용 가능).

### 엣지 케이스 (설계 확인 완료 — 구현 시 동작만 확인)
- 게이트 대기 중 회피 완료 → 위임 → 일반 이동(비전 이미 회피 완료라 wait-gate 즉시 통과). 정상.
- 목표까지 거리 < 20mm(단거리 재진입) → firstMove 조건 미충족 지속 → 회피 완료 or 타임아웃으로
  위임 → 단거리 일반 이동. 무해(원본도 동일 구조, 타임아웃이 커버).

## 5. 계측 로그 (필수 — 원본 필드 미러 + waitedMs)

`WriteLog("PickerPlaceSequence", ...)`, 배치당 게이트 1회 기준:
- **Wait**(최초 1회): `Place 팔로잉 시작 게이트 대기(선행 비전 퇴장/첫 명령 이동량). gateDistance={설정값}(OUTPUT SAFETY OFFSET), leadingActual=, leadingDeparture=, leadingMoving=, firstMove= - Wait`
- **Ok**(통과): 상동 수치 + `waitedMs=` ` - Ok`
- **Check**(위임): 사유(`reason=retreatCompleted|timeout`) + `waitedMs=` + 상동 수치 ` - Check`
- 게이트 비활성(설정 0 이하)일 때는 로그 없이 현행 그대로 진입(사이클마다 소음 방지).

폴백 합류는 기존 로그 재사용("팔로잉 진입이 실패해 기존 일반 이동으로 재시도합니다. followResult=-24").

  25로 설정 — 배치마다 게이트 Ok(`gateDistance=25`, waitedMs 수십 ms대) → `AX-FOLLOW-FIRST` 정상
  발행. **설정값 변경이 재시작 없이(또는 기존 Setup 반영 규칙대로) 게이트에 반영되는지 확인.**
  PickUp 쪽 로그 무변화 확인.
3. 시뮬 ②(위임): 비전 회피가 즉시 끝나는 조건(단거리 회피) — `reason=retreatCompleted` 위임 →
  일반 이동 정상 완료.
4. 실장비(굉음): 100% 속도 재현 조건에서 팔로잉 시작 직후 10ms `ModifyPosition` 연발이 감소하는지
  Motion 로그로 확인. **재현 시 앱 재시작 금지·Motion 로그 보존**(2026-08-27 분석 건 공유 규칙).
5. 실장비(후퇴): Place 주행 중 CYCLE STOP → STOP → 재시작 — 게이트 Wait → 위임 or 통과,
  **X 후퇴 명령 0건** 확인(자매 지시서 가드가 함께 배포됐다면 -25 로그도 0건이어야 정상 —
  게이트가 먼저 걸러내기 때문).

## 7. 롤백
게이트 루프 + 상수 4개 삭제만. 자매 지시서와 독립 롤백 가능.

## 8. 범위 밖 (지시 없음 — 건드리지 말 것)
PickUp 팔로잉 게이트 이식(`INPUT SAFETY OFFSET` 연결 포함 — 그 설정은 계속 미사용으로 둔다),
굉음 B안(오버라이드 최소 증분 3~5mm), 신규 설정/UI 추가(기존 OUTPUT SAFETY OFFSET 재사용으로 확정),
코디네이터 원본 수정, FollowMoveAsync 본체(자매 지시서 별건).
