## 1. 목표 동작 (사용자 확정)

### 1-A. 진입 오버랩 — PickerY 전진 ∥ 첫 피커 Z PrePick 하강 동시

```
PickUp 진입 시 PickerY가 픽업 작업위치로 전진을 "시작"하는 시점에
→ 첫 번째 피커의 Z를 PrePick(픽업 준비 높이 — 기존 PickerZPrePickDistance 파생값)까지
  내리는 이동을 "동시에" 비동기 시작
→ Y 전진 완료 후 Conti 노드 진입 시 Z PrePick 완료를 확인(join)하고 최종 픽업 하강 단계로
```
- **최종 픽업(접촉) 하강 + EjectPin/Needle 상승 동기 시퀀스는 무변경** — "접촉 하강은 XYT 최종 완료 후"라는 기존 원칙(2장 C6) 그대로. 선행은 PrePick 높이까지만.
- T는 선행하지 않음 — 기존 타이밍 유지 (Place 프롬프트와 동일 원칙).

### 1-B. 조기 완료 판정 — PickUp 후 Z 상승을 PrePick에서 끊기

```
픽업(진공 ON, die 부착) 후 Z 상승 시
→ Avoid까지 기다리지 않고 "PrePick 높이 도달" 시점에 픽업 완료 판정
→ 다음 die가 있고 그 die도 반경 게이트 안이면: 즉시 다음 피커 X 이동 (Z는 PrePick 높이 유지)
→ 다음 die가 반경 게이트 밖이면: 기존대로 Z 풀 상승(Avoid) 후 기존 순서로 진행
→ 마지막 die면: 즉시 픽업 종료 처리 진행 (기존 종료 정리 순서 무변경)
```
- Flow Check(흡착 확인) 등 픽업 완료 검증의 **내용과 실행 시점 원칙은 무변경** — 판정 높이만 변경 (4장 B3에서 전수 확인).

### 1-C. 발동 범위 — Needle 작업영역 반경 게이트 (신설, 핵심)

```
거리 = √( (die 목표 NeedleX − 중심X)² + (die 목표 StageY − 중심Y)² )
발동 조건: 거리 ≤ 신설 파라미터 (기본 130.0mm)
```
- **중심 좌표는 기존 Needle 작업영역 인터락의 중심을 그대로 재사용**: `stage.ResolveNeedleWorkAreaCenterX()/ResolveNeedleWorkAreaCenterY()` (InputStageInterlockRules.cs:1457-1460이 쓰는 것과 동일 소스). 새 중심 정의 금지.
- **판정 기준 = 해당 die의 목표 NeedleX/StageY 좌표 (맵 기준)** — 이동 시작 시점에 die 단위로 확정 판정. 실측 폴링 아님.
- **die 단위 적용**: 첫 die 진입 오버랩(1-A)과 die 간 Z PrePick 유지(1-B) 모두 이 게이트를 각 die에 대해 개별 판정. 반경 밖 die는 항상 기존 순서.
- Front/Rear **공통 게이트** (Place의 Rear StageY 제약과 달리 사이드 구분 없음).
- 존재 이유: 웨이퍼 가장자리에서 링/클램프 구조물과 물리 간섭 — 기존 반경 150 인터락(2장 C5)보다 안쪽의 "선행 허용 구역"을 정의. **기존 반경 150 인터락은 무변경 유지** (이 게이트가 대체하지 않음).

### 공통 게이트

1. Auto + 연속 픽업(ContiSegmentedPickUp) 모드일 것. 일반 모드는 기존 동작 그대로.
2. 신설 On/Off 스위치 On (기본 Off).
3. 반경 게이트(1-C) 충족.

### 신설 파라미터 (유닛 Config, 레시피 아님 — Bottom/Place 프롬프트와 동일 원칙)

- On/Off 스위치 (예: `PickUpEntryZPreDownMode` Off/On, 기본 Off)
- 발동 반경 (예: `PreDownNeedleWorkRadiusMm`, double, **기본 130.0**). 정규화 시 기존 Needle 작업영역 반경을 초과하지 않게 클램프하는 것을 계획 단계에서 검토.
- 위치: `PickerPickUpMotionConfig` (PickerTransferTypes.cs:43 — PickerZPrePickDistance가 사는 곳)에 [DataMember] 추가 + PickerFrontUnit/PickerRearUnit 프로퍼티 노출 (기존 노출 방식, PickerFrontUnit.cs:329-333 스타일). 설정 파일 하위호환(누락 시 기본값) 확인.

## 3. 수정 지점 (계획 단계에서 확정)

1. **[1-A] Y 전진과 동시 Z PrePick 비동기 시작**: C1의 PickerY 전진 발행 지점에서, 게이트(공통+반경) 충족 시 첫 피커 Z→PrePick 이동을 비동기 시작. Y 전진 완료 후 Conti 노드 진입 시 join — C2의 기존 X-트리거 PrePick 이동은 CanSkip/잔여 수렴으로 이중 명령 방지 (pending 1회 발행 구조, Bottom 프롬프트의 PendingBottomZDown 패턴 참고). join 실패 시 동기 1회 재시도 → 재실패 시 기존 Fail.
2. **[1-C] 반경 게이트 구현**: die 목표 NeedleX/StageY와 기존 중심(C5 재사용)으로 거리 계산 → 파라미터 비교. die 단위 판정 함수 1개로 통일해 1-A(첫 die)·1-B(다음 die 유지)에서 공용.
3. **[1-B] 상승 목표·완료 판정 변경**: C4의 상승을 "PrePick까지"로 변경, 도달 시 픽업 완료 판정. 다음 die 반경 안 → Z 유지 채 X 이동, 반경 밖 → 기존 풀 상승 폴백, 마지막 die → 종료 처리(기존 정리 무변경, PrePick에서 시작). Flow Check 등 완료 검증 로직의 내용·순서 무변경 확인.
4. **[Config] C3 클래스에 파라미터 추가** (1장 명세). 1-A/1-B를 같은 스위치로 묶을지 계획 단계 확정 (기본 Off 원칙).
5. **정리 경로**: 시퀀스 실패/CycleStop/배치 종료 시 선행 Z Task 정리, Z가 PrePick에 남은 예외 종료 시 정리 순서 (Z 정리 먼저 → Y 후퇴 — 기존 안전 순서 준수).
6. 신규 분기 로그 추가 (die별 반경 판정값·중심·임계값, 선행 시작 시점, join 대기 ms — 수정 후 로그 검증용).
