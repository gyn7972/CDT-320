5. **계측 필수**: 설정 변경·이관·리셋마다 old→new 수치를 로그로 남겨서, 실장비 로그만으로

7. 시뮬레이션(또는 오프라인 실행)에서 UI·영속·반영 확인 후 실장비 적용.

## 1. 배경과 현재 구조

### 1-1. 필터 한계 3종이 하드코딩/JSON 직수정 상태 (Pick·Place 동일 구조)

| 항목 | 현재 값 | 위치 | 문제 |
|---|---|---|---|
| ① 이상치 거부 한계(입력 클램프 — 큰 값 반영 안 함) | X/Y 1mm, T 1° | 각 Service **const** (Place :23~25, Pick 동형) | 조정에 빌드 필요. Place 쪽 주석("3으로 완화")과 코드값(1) 불일치 |
| ② 필터 상태 클램프 한계(발산 방지) | X/Y ±0.5mm, T ±1° | 각 Service **const** | 조정에 빌드 필요 |
| ③ 컷오프 fc(cycles/sample) | 0.1 | `Config\place_runtime_offset.json` / `pick_runtime_offset.json` | UI 없음. 파일은 런 중 지연 저장으로 덮어써져 앱 종료 상태에서만 수동 편집 가능 |

### 1-2. Pick 기구 이관·리셋이 미완 상태

`RuntimeOffsetMonitorDialog`(Pick/Place 모니터)는:
- **Place**: 이관 버튼 활성 — `기구 = 기구 − 필터`(X/Y, T 제외) → 기구 한계 자동 클램프 →
  이관 채널 `ResetXy`(이중 보정 방지) → `SaveMachineSettings` → 로그. 운전/초기화 중 금지
  게이트(`CanApplyMechanicalOffset`).
- **Pick**: 이관 버튼이 **비활성(안내만)** — "부호 확정 전" (:76~81). 명시적 리셋 버튼은
  Pick/Place **둘 다 없음** (Place는 이관 시 자동 리셋만 존재).
- `PickRuntimeOffsetService`에는 `GetSnapshot`/`ResetXy`/`Reset`/`ResetAll` API가 **이미
  전부 있다** — 빠진 건 UI와 이관 부호 확정뿐.

### 1-3. ★Pick 이관 부호 분석 (이번 세션 코드 확인 결과)

적용 산식(DieCoordinateTransformService):

| 항 | 진입점 | 부호 |
|---|---|---|
| Pick 런타임 X | `CalculatePickTarget` → PickerX·NeedleX (:105, :110) | **+** |
| Pick 런타임 Y | `CalculatePickTarget` → **StageY** (:104) | **+** |
| Pick 런타임 T | PickerT (:108) | − |
| Pick 기구 X | `ApplyPickMechanicalOffsets` → PickerX·NeedleX (:141~142) | **+** |
| Pick 기구 Y | `ApplyPickMechanicalOffsets` → **PickerY** (:143) | **+** |

- **X: 이관식 확정 가능** — 런타임과 기구가 **같은 진입점(PickerX/NeedleX)에 같은 부호(+)**
  → `기구X′ = 기구X + 필터X` 로 총합 불변 이관. (Place가 −인 것과 반대 — Place는
  런타임 −/기구 + 였기 때문)
- **Y: 코드만으로 확정 불가** — 런타임은 **InputStage Y축**, 기구는 **Picker Y축**으로
  **서로 다른 축**에 들어간다. 두 축의 + 방향이 물리적으로 같은지/반대인지에 따라
  `기구Y′ = 기구Y ± 필터Y` 가 갈린다. **이것이 기존 버튼이 비활성이었던 이유**로 판단.
  부호가 틀리면 오차가 상쇄가 아니라 **2배**가 되므로 §6-1 절차로 확정 후 활성화한다.
- **T: 기구 대응 항 없음** — Place와 동일하게 이관 제외(표시 전용).

### 1-4. 운영 주의 (범위 아님)
후검사 X +1.15mm 측정기준 상수 방치 상태에서 Place 이상치 한계(1mm)를 1.15 초과로
올리면 X 편향이 필터에 학습되기 시작한다. Enable 금지 조건과 함께 운영 주의.

## 5. 검증 (실장비 전에 반드시)

### 5-1. 정적 확인
- `/p:OutDir=<임시경로>` 빌드, 수정 파일 신규 경고 0건.
- const 8개(2서비스×4) 잔여 참조 0건. 판정 알고리즘 diff가 "인자 교체뿐"인지 육안 확인.
- UI 저장 경로가 `SetFilterSettings`/이관·리셋 API 단일 경유인지 확인.

### 5-2. 설정 다이얼로그 (Pick/Place 각각)
1. 현재값 표시(기본 fc 0.1 / 1 / 1 / 0.5 / 1) + alpha 환산.
2. 저장 → json 즉시 반영 + 변경 로그. 3. 재기동 후 유지. 4. 구버전 json 폴백.
5. fc 변경 → 8세트 Value 불변, 이후 갱신부터 새 alpha.
6. 이상치 한계 상향/하향 → 동일 샘플 반영/폐기 전환 확인.
7. 클램프 축소 → 즉시 재클램프 + 로그. 8. 범위 밖 입력 거부.
9. 런 중 변경(§6-3 허용 시) → 다음 샘플부터 적용, 예외 없음. 10. 무사용 회귀.

### 5-3. Pick 이관·리셋
1. 운전 중 이관/리셋 → 차단 메시지(Place와 동일 게이트).
2. Pick 이관(X): 필터 0.1 상태 이관 → 기구X +0.1, 필터 0, 총합 불변 —
   이관 전후 `CalculatePickTarget` 로그의 PickerX 동일 확인.
3. **Pick 이관(Y) 실장비 부호 확정 절차(§6-1)**: 한 픽커만 소량(0.05mm) 이관 →
   다음 픽업 Bottom 검사 Y 오프셋이 **0으로 수렴하는 방향**인지 확인. 반대로 커지면
   부호 파라미터 반전 후 재확인. 확정 후 전 픽커 활성화.
4. 기구 한계 클램프 발생 케이스 → 안내 + Warning 로그.
5. 리셋(PICK/PLACE 각각): 확인 다이얼로그 → 8세트 0 + json 반영 + 리셋 전 값 로그.
6. 이관 후 이중 보정 없음: 이관 채널 필터 0에서 재학습 시작 확인.
7. 모니터 그리드 표시(필터/기구 열) 이관·리셋 직후 즉시 갱신.
