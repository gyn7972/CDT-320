# 바텀 Offset 촬영각 프레임 변환 — 설계 (2026-08-25, 팀장님 지시)

## 배경 — 정적 편심 보상(3cc985e8) 폐기 사유

커밋 3cc985e8의 픽 목표 정적 보상 ΔP=(I−R(Δθ))(C−O)는 "저장 픽커 좌표↔물체 위치"의
방향이라는, 코드에 존재하지 않는 부호를 새로 정해야 했고(부호 유보), 실장비 1런에서
X가 반대 방향으로 확인됐다. 팀장님 재설계 지시(2026-08-25):

> 0도 픽업/0도 촬영은 부호가 이미 실장비 확정된 클로즈루프다. 0도 픽업/180도 촬영이
> 추가되는 것이니, 비전PC에서 Offset이 넘어오면 **회전의 중심 기준 −180° 회전**시켜
> 그 값을 기존 클로즈루프(Pick 런타임 필터)에 넣으면 된다. 새 보상식·새 부호 결정 불요.
> 촬영 각도는 레시피(티칭)를 따라가므로 각도에 따라 분기한다.

정적 보상은 전량 리버트(7파일 원복 — 보상 이전 커밋과 diff 0 확인), **COC 저장
SaveSettings 보강만 존치**(새 방식도 C를 실시간으로 읽으므로 F13 재시작 구값 문제 여전).

## 변환식

- 기계 프레임: `m′ = R(−Δθ)·(m − a) + a`,  a = 촬영지령XY − C (회전축의 광축 기준 위치,
  Side 90° Y 절대식과 동일 재료·부호 — 실장비 검증 선례 F8)
- Δθ = 티칭 PickPosition T − 티칭 BottomPosition T (±360 정규화)
- |Δθ|≈180°: R(±180)=−I → **m′ = 2·(촬영지령 − C) − m** (회전방향 무관)
- 프레임 환산 필수: 비전 Offset은 이미지 프레임 mm(X=기계 동일, **Y=기계 반대**,
  BottomVisionOffset 주석 확정) — 기계로 환산해 변환 후 이미지로 되돌려 기존 체인
  (Y P4 전처리 포함)에 그대로 태운다. 전처리·필터·적용 부호는 **무수정**.

## 정합성 검증(대수)

완벽 픽(δ=0), 픽커 P에서 180° 촬영: 콜렛중심 = P−O(O가 촬영각 측정이므로 직접),
다이 = (P−O) − δ. 변환: m′ = 2(P−C) − (P−O) + δ = (P − O₀°) + δ, O₀°=2C−O(0°자세
콜렛원점) — **0° 촬영이었다면 나왔을 raw와 정확히 일치**. 편심(2e)은 변환 항에 실려
필터가 함께 학습·흡수한다(정적 보상 불필요해지는 이유).

## 분기(레시피 티칭 기반)와 게이트

| 조건 | 동작 |
|---|---|
| \|Δθ\| ≤ 5° | 무변환 — 기존 경로와 완전 동일(현행 0/0 레시피 무영향) |
| \|\|Δθ\|−180°\| ≤ 5° | m′ = 2(촬영지령−C) − m 변환 후 학습 |
| 그 외 각도 | 샘플 폐기 + Check 로그(비검증 각도 프레임 학습 방지) |
| 180°인데 C 사용 불가(Config Valid=false 또는 record.Valid=false 또는 RotationCenterUpdatedAt<UpdatedAt) | 샘플 폐기 + Check 로그(무변환 학습은 반대 프레임이라 금지) |

Place 감산 쪽 MRESULT 사용은 촬영각=플레이스각이라 **무변환 유지**. 픽 산식·인터락 무수정.

## 계측

PICK-RUNTIME-OFFSET 로그에 shootFrame(pickAngle/oppositeAngle), deltaThetaTeaching,
rotationCenter(usable), capturedPickerXCommand, axisFromCameraMach, measuredX/effectiveX,
rawOffsetY/effectiveRawY 추가 — 실런 1회로 변환 전/후·판정 근거 확정 가능.
