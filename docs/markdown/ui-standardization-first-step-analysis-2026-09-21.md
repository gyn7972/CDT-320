## 가장 먼저 검증할 구조

기존 카탈로그와 UiTheme를 수정하지 않고 다음의 작은 구조만 검토한다.

| 구성 | 책임 | 하지 않는 일 |
| --- | --- | --- |
| 새 `UiStandardPalette` | 새 표준 버튼의 역할별 색상 정의 | 기존 테마 변경, 설정 읽기, 언어 처리, 장비 상태 판단 |
| 새 `UiStandardButton : Button` | Designer에서 선택한 역할의 색상 사용 | 위치·크기·Dock 자동 배치, 장비 이벤트, 자체 그리기 엔진 |
| 새 독립 Preview Form + Designer | 실제 공용 버튼을 배치하고 편집·저장·재열기 검증 | 생산 메뉴 등록, PageBase 상속, 로그/장비 연결 |

핵심은 런타임의 `ApplyTheme(this)` 호출이 아니다. Designer 안에서 `new UiStandardButton()`으로 컨트롤을 만들고, 역할은 속성 창에서 선택하며, 위치·크기·여백은 기존 WinForms 속성으로 편집하는 방식이 가능한지 검증하는 것이다.

이 방식은 아직 구현·Designer 검증되지 않은 제안이다. 기본 색상과 개별 색상 override가 Designer 저장 과정에서 충돌할 수 있으므로, 코드 컴파일만으로 "사용 가능"이라고 판정하지 않는다.

### 색상 중앙 관리와 개별 편집의 구분

- 기본 역할을 사용하는 버튼: 팔레트 변경 후 재빌드하고 새로 열면 변경 색상이 반영되어야 한다.
- 사용자가 Designer에서 명시적으로 다른 색상을 지정한 버튼: 그 개별 설정이 저장·재열기 후 유지되어야 한다.
- 개별 색상을 Reset하면 역할의 기본 색상으로 돌아가야 한다.
- 프로그램 실행 중 즉시 모든 화면에 색상을 전파하는 기능은 요구하지 않는다. 이를 위한 전역 이벤트·타이머를 만들지 않는다.
- 기존 운영 버튼은 교체하지 않았으므로 영향을 받으면 안 된다.
- 역할 색상 관리와 S/M/L 크기 관리를 한 번에 추상화하지 않는다. 첫 검증의 S/M/L은 Designer의 명시적인 Size/Font 예제로 둔다.

## EventLog 적용 시 별도로 풀어야 할 문제

### 1. 현재 버튼 크기를 S/M/L로 곧바로 바꿀 수 없다

- 현재 필터 행 40px, 위·아래 Padding 합계 6px → 내부 높이 34px.
- 현재 버튼 높이 24px.
- 카탈로그의 96 DPI 기준 S/M/L 높이는 36/44/52px다. S도 현행 내부 높이보다 크다.
- 카탈로그는 120 DPI 저장(버튼 112×45 / 150×55 / 200×65), 템플릿은 96 DPI 저장이다.
- EventLogPage Designer에는 AutoScaleMode/Dimensions가 명시되지 않으므로 부모 배율과 실제 화면을 확인해야 한다.
- REFRESH는 열 폭 122px에서 좌우 Margin 8px을 빼면 114px인데 MinimumSize 너비가 116px이다. 기존 최소 폭 불일치도 후속 배치 검토 대상이며 이번 Common 검증에서 함께 수정하지 않는다.

따라서 기존 위치·열 구조를 보존하면서 색상만 적용하는 작업과, 필터 행 높이·여백을 조정하는 크기 작업을 분리한다. 카탈로그의 저장 픽셀이나 코드 전체를 복사하지 않는다.

### 2. 동적 의미색을 정적 테마와 혼동하면 안 된다

EventLogPage의 `BuildRow`는 Warning/Alarm/Work/각 시퀀스 등의 행 글자색과 알람 굵은 글꼴을 지정한다. 공용 버튼 검증 또는 정적 Designer 적용 과정에서 이를 검정/주황으로 일괄 덮어쓰지 않는다. 의미색 공용화가 필요하면 해당 UI 표시 함수와 새 표시 팔레트만 별도 승인받는다.

### 3. 검색 성능은 별도 변경이다

현재 검색 입력은 `FilterTextBox_TextChanged`에서 즉시 캐시 검사·그리드 재구성을 요청한다. 10,000행 검색의 응답성은 추가 확인 대상이다. 이번 공용 버튼 검증에 검색 지연 실행, 캐시 교체, 타이머·스레드 변경을 섞지 않는다.

## 권장 진행 순서와 승인 경계

1. **이번:** 현재 구조 분석, 첫 검증용 프롬프트 작성. 문서만 변경.
2. **첫 구현 승인 후:** Common의 공용 버튼·팔레트·독립 Preview만 추가. 생산 화면 수정 0개.
3. **Designer 검증 결과 승인 후:** EventLogPage 정적 버튼/스타일만 첫 적용. 변경 파일과 속성 목록을 다시 확정.
4. **별도 승인 후:** S/M/L 크기·여백 조정. 기존 배치의 변화량을 먼저 제시.
5. **별도 승인 후:** 필요한 Label/TextBox 등 공용 타입을 하나씩 검증·확장. 단일행 입력 동작을 크기 맞추기 위해 바꾸지 않는다.
6. **별도 승인 후:** EventLog 검색 성능과 동적 표시색을 각각 독립 작업으로 진행.
7. 위 결과가 안정되면 다른 조회·편집·장비 화면을 영향도에 따라 순차 검토한다. 자동으로 다음 단계에 착수하지 않는다.

"프로그램 전체 UI 공용화 완료"는 위 일부 단계만 끝내고 사용할 수 있는 표현이 아니다. 단계별로 공통 기반 검증, 화면 적용, 현장 검증을 구분해 보고한다.
