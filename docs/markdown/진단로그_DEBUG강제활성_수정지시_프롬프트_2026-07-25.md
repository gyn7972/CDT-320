# 배경 — 현재 동작과 요구사항

## 현재 구조
`QMC.Common\Logging\LogPolicy.cs`가 로그 저장 정책의 중앙 관리자다.
- `LogMode.ProductionMinimal`(기본) / `LogMode.DiagnosticVerbose`
- `_mode` 필드 기본값은 `ProductionMinimal`(`:44`)
- `DiagnosticVerbose`는 **제한 시간(최대 1440분)** 후 `Mode` getter(`:71`)에서 자동으로
  `ProductionMinimal`로 복귀한다
- 활성화 경로 2개:
  - `AppSettings.ApplyLogPolicySettings`(`:261`) — `LogDiagnosticVerboseOnStart` 설정이 true일 때
  - `LogSettingsPanelControl`(`:119`) — 사용자가 ENABLE 버튼 클릭

## 저장 판정의 단일 관문
상세 로그 저장 여부는 **`LogPolicy.IsDiagnosticVerbose`(`:78`) 하나**로 갈린다. 소비 지점 전체:
- `QMC.Common\Logging\Log.cs:26`, `:33`, `:44` — Motion/Main 등 상세 로그 기록 게이트
- `QMC.Common\Logging\LogPolicy.cs:206` — `ShouldPersist` 내부
- `QMC.CDT-320\Ui\Controls\LogSettingsPanelControl.cs:162` — UI 표시(`Mode` 직접 비교)

따라서 `Mode` / `IsDiagnosticVerbose`만 DEBUG에서 고정하면 저장 경로 전체가 함께 켜진다.
**`Log.cs` / `EventLogger.cs`는 수정할 필요가 없다.**

## 요구사항 (사용자 지시 2026-07-25)
1. **DEBUG 빌드**: 프로그램 시작과 동시에 진단 상세 로그 **활성화**. 만료·해제 없이 유지.
2. **RELEASE 빌드**: 기존과 동일 — 사용자가 UI에서 켠다(제한 시간 + 자동 복귀 유지).

`DEBUG` 심볼은 두 프로젝트 csproj의 Debug 구성에 이미 정의되어 있다
(`QMC.CDT-320.csproj:22`, `:40` / `QMC.Common.csproj:21`, `:37` — `DefineConstants: DEBUG;TRACE`).
`LogPolicy.cs`는 `QMC.Common`에 있으므로 그 프로젝트의 `DEBUG` 심볼을 따른다.
**csproj는 수정하지 않는다.**

```csharp
        ///           활성화하고 만료·해제되지 않는다. RELEASE 빌드는 기존 동작(사용자 조작 + 제한 시간)을
```

### A-4. `DiagnosticVerboseRemaining` (`:84~96`)
DEBUG에서는 만료가 없으므로 무한을 뜻하는 값을 돌려준다. UI가 남은 시간을 표시하지 않도록
`TimeSpan.MaxValue`를 쓴다.
```csharp
        public static TimeSpan DiagnosticVerboseRemaining
        {
            get
            {
#if DEBUG
                // DEBUG 빌드는 만료가 없다. UI는 IsDiagnosticVerboseForcedByBuild로 분기한다.
                return TimeSpan.MaxValue;
#else
                lock (SyncRoot)
                {
                    if (_mode != LogMode.DiagnosticVerbose)
                        return TimeSpan.Zero;
                    TimeSpan remain = _diagnosticExpireAt - DateTime.Now;
                    return remain > TimeSpan.Zero ? remain : TimeSpan.Zero;
                }
#endif
            }
        }
```

### A-6. 시작 시 1회 감사 로그
`Configure`(`:121`)는 시작 시 `AppSettings.ApplyLogPolicySettings`에서 호출된다.
DEBUG일 때 강제 활성화 사실을 **1회만** 남긴다(재호출 대비 once 플래그).

`Configure` 메서드 위에 필드 추가:
```csharp

```
`Configure` 본문 끝(`lock` 블록 밖)에 추가:

## 검증 기준
**Debug 구성으로 실행**
1. 프로그램 시작 직후, 사용자가 아무 조작도 하지 않은 상태에서 `Motion` / `Main` 상세 로그가
   디스크에 기록된다(예: `AxisMoveProfile`, `MotionGuard` 라인이 파일에 남는다).
2. 시작 로그에 `DEBUG 빌드 — 진단 상세 로그(DiagnosticVerbose)를 프로그램 시작과 동시에 강제
   활성화했습니다. 해제 불가.` 감사 항목이 **1회만** 남는다.
3. LOG 설정 화면에서 상태 문구가 `DEBUG 빌드는 시작과 동시에 강제 활성화되며 해제할 수 없습니다`로
   표시되고, ENABLE / DISABLE 버튼과 분(minutes) 입력이 모두 비활성이다.
4. 장시간(설정 만료 시간 초과) 운전 후에도 상세 로그가 계속 기록된다(자동 복귀 없음).
5. `AppSettings`의 `LogDiagnosticVerboseOnStart`를 `false`로 두어도 상세 로그가 켜진다
   (설정과 무관하게 강제).

**Release 구성으로 실행**
6. 시작 직후에는 `ProductionMinimal`이고 상세 로그가 디스크에 남지 않는다.
7. LOG 설정 화면에서 ENABLE 버튼이 활성이고, 클릭하면 상세 저장이 시작되며 남은 시간이 표시된다.
8. 제한 시간 만료 후 `ProductionMinimal`로 자동 복귀하고 감사 로그가 남는다.
9. DISABLE 버튼으로 즉시 해제된다.
10. `LogDiagnosticVerboseOnStart = true`이면 시작 시 자동 활성화된다(기존 동작 유지).

## [확인 요청 1] — RELEASE 회귀 없음 근거 (보고 필수)
`Mode` / `DiagnosticVerboseRemaining`을 조건부 컴파일로 나누면서 RELEASE 경로가 바뀌지 않았음을
`git diff`로 증명하라. 특히 `lock (SyncRoot)` 범위, 만료 판정
(`DateTime.Now >= _diagnosticExpireAt`), `RevertToProductionMinimalNoLock` 호출이 RELEASE에서
그대로인지 확인해 보고한다.

## 알려진 잔여 사항 (이번 범위 아님 — 보고만)
1. DEBUG 빌드는 상세 로그가 항상 켜지므로 로그 용량이 크게 증가한다. 오늘(2026-07-25) 실제로
   `D:\CDT-320\Log\Event`에 100MB 단위 CSV가 다수 생성돼 있었다. 블랙박스 용량
   (`LogBlackboxCapacity`)이나 보존 정책(`LogRetentionService`) 조정이 필요할 수 있으나
   **이번 작업 범위가 아니다.**
2. `AppSettings.LogDiagnosticVerboseOnStart` 설정은 DEBUG에서 의미가 없어진다(항상 강제 활성).
   설정 화면에서 이를 안내하거나 숨기는 처리는 별도 결정 사항이다.
