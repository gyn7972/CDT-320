# Material 저장·UI 지연 개선 구현 프롬프트

현재 로컬 코드와 `D:\Source\DATA_LOG`의 장비 로그를 기준으로 Material 저장 실패와 Recipe/Config 편집 후 일시적인 UI 멈춤을 해결한다. 저장소 작업 규칙은 `AGENTS.md`, 검증 현황은 [체크리스트](01-checklist.md), 시퀀스 영향 제안은 [변경안](02-approval-plan.md), 수동 기능의 실제 동작은 [흐름 분석](03-manual-state-flow.md)을 따른다.

## 완료 기준

작업자가 GUI에서 변경한 GOOD/WAIT/NG/SKIP/FLYING, 매핑, Clear와 Recipe/Config 값이 화면·Material·저장 파일·다음 운전에서 일치해야 한다. 실장비에서 이미 사용하는 수동 변경 기능을 제한하거나, 입력값을 조용히 예전 값으로 복원해서 문제를 숨기지 않는다. 저장 실패를 성공으로 표시하지 않는다.

## 저장·UI 구현 범위

1. Material Snapshot의 typed clone 구조 검사와 현재 모델을 맞추고 모든 필드·중첩 객체·검사 상세 저장 정책의 동등성을 검증한다. 직렬화 키와 원자적 파일 교체 계약을 유지한다.
2. 일반 Recipe/Config 항목 편집에서는 기존 setter와 runtime 반영 시점을 유지한다. 전체 Machine 동기 저장을 해당 Unit의 기존 저장 권한에 맞는 독립 사본 저장으로 줄이고, 파일 쓰기를 UI 밖에서 순차 처리한다.
3. BaseAxis의 MotionAxisStore 권한, 실 DI/DO의 Setup 제외, Vision의 별도 Calibration 저장, Picker T의 Machine.Recipe 원본을 보존한다.
4. 사본을 만드는 과정에서 역직렬화의 기본값 보정이 현재 편집값을 변경하지 않도록 한다. 같은 파일의 동기/비동기 저장은 최신 요청 순서를 공유하고, 실패 시 최신 미저장값을 재시도 대상으로 유지한다.
5. 일반 화면 전환에 저장 완료 대기를 추가하지 않는다. 명시적 Recipe 적용/복사/삭제/이름변경과 종료는 최신 저장을 비동기로 확인한 뒤 진행한다. 저장되지 않은 값을 복사하거나 이전 저장 요청이 새 Recipe 경로를 덮지 않게 한다.
6. UI 표시 전용 Material 조회는 잠금이 바쁘면 다음 표시 주기로 미룬다. 해당 표시값을 제어·자재 유무 판단에 사용하지 않는다. 기존 잠금 통계의 대기/처리를 구분한다.

## 승인 후에만 구현할 Material 변경

아래는 승인 요청을 구체화하는 작업 항목이다. 이 문서 자체가 인터락/시퀀스 변경 승인은 아니다.

- 일반 재매핑과 Input WAIT의 명시적 재픽업 복구를 구분한다. GUI에서 이미 확정한 상태와 WAIT 복구 결과를 보존하면서, Die의 부모·Output 슬롯 역참조를 함께 갱신한다.
- Input/Output 수동 상태 편집은 전체 선택의 ID·wafer 세대·현재 상태를 먼저 확인하고 동일한 Material 잠금에서 반영한다. SKIP과 FLYING 의미를 구분하고 중간 상태가 저장되지 않게 한다.
- 실제 배치된 Output의 WAIT 재사용은 사용자 사용 의도와 실물 확인 절차를 확정한 후 구현한다. 임의로 재사용을 막거나 점유 UID 하나만 지우지 않는다.
- Input Clear는 정상 Output 이력을 유지하고 카세트 초기화 후 다음 START에서 매핑하는 기존 경로를 보존한다. 모순된 역참조가 있으면 삭제 전에 구체적인 원인을 반환한다.
- UI는 변경 거부, 메모리 반영, 파일 저장 완료를 구별한다. 저장에 실패한 상태를 성공이라고 안내하지 않는다.
- 축·센서·충돌 인터락, 자동 승인, 운전 중 Recipe 적용 정책, 진행 중 새 대상·새 순서 허용 정책을 함께 변경하지 않는다. 필요하면 별도 변경안과 승인을 요청한다.

## 검증과 보고

격리된 데이터로 연속 저장·저장 실패/재시도·Recipe 복사/전환·종료·값 동등성을 검증한다. 수동 상태는 버튼 적용부터 실제 다음 후보와 저장 후 재로드까지 추적한다. 테스트용 UI의 임의 상태나 검사 생략을 실장비 성공 근거로 사용하지 않는다.

수정 파일만 인코딩/공백 검사와 별도 출력 폴더 Build를 수행한다. 다른 작업의 변경, 운영 데이터, 장비 실행 파일은 손대지 않는다. 완료한 수정·검증 결과·미승인 항목·현장 확인 항목을 분리해 보고한다.
