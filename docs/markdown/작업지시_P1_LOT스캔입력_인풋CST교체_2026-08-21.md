## 2. 작업 B — INPUT `CST EXCHANGE` 버튼 (모션: 리프터를 카세트 넣기 좋은 위치로)

### 배경 (코드 확정)
- 요구: "카세트 놓기 좋은 위치를 버튼 한방으로" — 아웃풋에는 완성형이 이미 있다:
  `OutputCassettePage.cs:548-624` `PrepareCassetteExchangeAsync` = AutoRunning 차단 →
  3단계 안내 확인창 → 피더 회수/후퇴 → **리프터를 레시피 로딩 포지션으로 이동**
  (교체 높이는 별도 티칭 없이 로딩 포지션 재사용 — 사용자 확정 2026-07-26).
- 인풋에는 `LIFTER READY`(준비/Avoid 위치, `InputCassettePage.cs:389-420`)만 있고
  로딩 위치 원버튼이 없다.
- 인풋 티칭값은 이미 존재: `InputCassetteUnit.cs:82 Recipe.LoaingPosition`(오타 명칭
  그대로 사용할 것, 기본 150.0). 이동 API `MoveWaferLifterZ` / 레시피 페이지의
  "LOADING MOVE"(`InputCassetteRecipePage.cs:226`)가 같은 좌표로 이동 중.

### 변경 (2파일)
`Ui\Pages\WorkInfo\InputCassettePage.Designer.cs`
- ACTION 패널에 `btnCstExchange` ("CST EXCHANGE") 추가. 기존 레이아웃 좌표 불침범.

`Ui\Pages\WorkInfo\InputCassettePage.cs`
- `CompleteInputCassetteExchangeAsync` 아님 — **모션 준비 함수** `PrepareInputCassetteExchangeAsync`:
  1. 컨트롤러 상태 가드: Output `CanChangeOutputCassetteData`(:279-310) 미러
     (AutoRunning/수동 시퀀스/Ready 실행 중 차단).
  2. **진행 자재 가드**: InputFeeder/InputStage에 웨이퍼 있으면 **차단+사유 안내**
     (아웃풋처럼 자동 반납 시퀀스를 돌리지 않는다 — 1차 버전은 차단이 안전.
     반납까지 원버튼은 별도 지시).
  3. 피더 물리 안전 확인: 피더 Avoid + Lift Down 상태 확인(기존 확인 API 재사용 —
     구현 시 `IsWaferFeederAvoidPositionCheck`/`IsWaferFeederDown` 확인). 불충족 시 차단.
  4. 확인창: "INPUT 리프터를 카세트 교체(로딩) 위치로 이동합니다. 진행할까요?"
  5. `InputLifterZ` ServoOn 확인 → `Recipe.LoaingPosition`으로 이동 (기존 이동
     API 재사용 — LIFTER READY 핸들러의 ServoOn/대기 패턴 미러).
  6. 완료 안내: "카세트를 교체하십시오. 교체 후 [CST CLEAR]를 눌러 데이터를
     초기화하면 다음 START에서 매핑부터 재진행됩니다."
- Enable 관리: 기존 ACTION 버튼 Enabled 갱신 경로에 포함.
