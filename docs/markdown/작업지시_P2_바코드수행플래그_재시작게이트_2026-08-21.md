## 1. 요구 (팀장님 원문 기준)

1. 로딩 중 알람 → 재시작 시 현재는 무조건 AlignT부터 재개된다. **바코드 사용 모드에서
   바코드 정보가 없거나 바코드 시퀀스를 수행하지 않았으면 바코드 시퀀스부터 재개**해야 한다.
   재시작 시 인터락·진행 상황 확인 후 진행.
2. **바코드 시퀀스 수행 여부 flag**를 자재에 보관해야 한다 — 나중에 이 웨이퍼 ID가
   ① 리더 판독인지 ② 판독 실패 후 수동 입력인지 ③ 바코드 미사용 모드의 임의 생성
   번호인지 구분할 수 있어야 한다.
3. 아웃풋 바코드도 인풋과 동일하게 동작 (재시작 규칙 포함) + 시퀀스 실장비 검증.

## 2. 코드 현황 (조사 확정)

- **재시작이 AlignT로 가는 원인**: `Sequencing\InputSequence.cs:1412-1476`
  `ResolveStageWaferResumeStep` — "Stage에 웨이퍼 + Align 결과 없음 → AlignStage"만
  판정하고 `BarcodeConfirmed`를 안 본다. 바코드 스텝은 그 앞 이적재 시퀀스 내부
  (`InputFeederLoadToStageSequence` step `RunBarcodeSequence`, enum :31)라 영영 건너뜀.
- 하위 시퀀스 재개 저장소 `SequenceResumeStore`는 **메모리 전용**(디스크 없음) —
  앱 재시작 시 소실되므로 하위 재개에 의존하는 설계는 금지.
- 바코드 판독 코어(재사용 대상): `InputFeederLoadToStageSequence.cs:463-736`
  `RunBarcodeSequenceAsync` — 피더 안전 확인(`VerifyFeederSafeForInputBarcodeMotion`,
  알람 `IN-BARCODE-FEEDER-SAFE`) → ExpanderZ 하강 → VisionX `BarcodePosition` →
  StageY `BarcodePosition`+리트라이 오프셋(소프트리밋 사전검증 포함) → 스캔 →
  적용/실패 시 작업자 복구창(Retry/ManualApply/Cancel).
- 적용 지점: `MaterialStateService.WaferMove.cs:198-380` `TryApplyWaferBarcode` —
  한 lock에서 WaferId/BarcodeId/`BarcodeConfirmed=true`/`BarcodeSource`/연관 다이·슬롯
  포인터 원자 갱신. `sourceKind`("Reader"/수동)는 문자열로만 전달됨.
- 기존 자재 필드: `MaterialModel.cs:455-463` — `BarcodeConfirmed`(적용 여부),
  `BarcodeSource`(문자열). **"시퀀스를 실제 수행했는가"를 답하는 필드는 없음.**
- 중복 판독 방지 게이트(유지할 것): `InputFeederLoadToStageSequence.cs:492-508` —
  재개 시 `BarcodeConfirmed && IsUsableBarcode`면 재판독 생략.
- 아웃풋: `OutputFeederLoadToStageSequence.cs` `RunBarcodeSequence`(enum :41) 존재,
  Good/NG 좌표 분기 완비. **없는 것**: 바코드 꺼짐 안내(인풋 전용
  `BarcodeDisabledNoticeService` 참조는 `InputSequence.cs:3521,3531` 2곳뿐), 재개 게이트.

## 3. 작업 항목

### A. 수행 플래그 (자재 모델)
1. `WaferMaterial`에 `[DataMember] public bool BarcodeSequencePerformed`
   (+ 필요시 `BarcodeOrigin` 문자열: "Reader"/"Manual"/"" — 기존 `BarcodeSource`가
   이미 sourceKind를 담고 있으니 **신규 필드는 bool 1개를 기본안**으로, Origin은
   BarcodeSource 규약 정리로 갈음. 구현 시 BarcodeSource에 들어가는 실제 문자열
   확인 후 결정).
2. 마킹 시점: `RunBarcodeSequenceAsync`에서 **첫 리더 판독 시도가 실제 실행되는 순간**
   (스킵 경로 제외). 수동 입력(ManualApply)은 시퀀스 안에서 일어나므로 자동으로
   "수행 O + 수동"이 된다. 바코드 미사용 모드는 스텝 자체를 스킵 → false 유지.
3. 저장: `MaterialStateService`에 마킹 API 1개 (lock + NotifyAndSave). 
   **주의**: `MaterialSnapshotStore`의 타입 클론(`CloneSnapshotTyped`)에 신규 필드
   반영 필수 — 누락 시 property-count 가드가 reflection 폴백으로 떨어져 저장 성능
   저하(51배 최적화 무효화). CSV/스냅샷 영속 확인.
4. 아웃풋 자재에도 동일 필드 적용 대상 확인 (아웃풋 바코드가 갱신하는 자재 구조를
   구현 시 확인 — 인풋과 같은 `WaferMaterial`이면 필드 공유).

### B. 인풋 재시작 게이트
1. 게이트 조건: `AppSettings.UseInputWaferBarcode && stage 웨이퍼 존재 &&
   (!wafer.BarcodeSequencePerformed || !IsUsableBarcode(wafer.BarcodeId))`.
2. **권장 구현: AlignStage 진입부 게이트** (`InputSequence.Steps.Align.cs`
   `ExecuteStepAlignStageAsync` 시작부) — 새 auto step enum 추가 없이:
   게이트 성립 시 "스테이지 바코드 판독 코어"를 먼저 실행하고 정상 흐름 계속.
   - 판독 코어는 `RunBarcodeSequenceAsync`의 스테이지 구간을 **공용 메서드로 추출**해
     이적재 스텝과 재시작 게이트가 같은 코드를 쓴다 (복제 금지).
   - 인터락 요구 충족: 추출 코어에 피더 안전 확인 + 소프트리밋 검증이 이미 포함.
   - 대안(검토용): `InputSequenceAutoStep`에 바코드 복구 스텝 신설 — enum/전이 변경이
     커서 비권장. 팀장님 별도 지시 시에만.
3. `ResolveStageWaferResumeStep`은 무변경이 기본안 (게이트를 Align 진입부에 두므로).
   단, 재개 로그에 바코드 게이트 판정 결과 1줄 추가 (가시성).

### C. 아웃풋 대칭
1. 아웃풋 재개 판정 구조 조사 (OutputSequence 쪽 — 인풋 `ResolveStageWaferResumeStep`
   상당 지점 확인) 후 **동일 게이트** 적용.
2. `UseOutputBinBarcode=false && Auto` 시 안내창 — `BarcodeDisabledNoticeService`
   재사용, 인풋 문구 미러 (`InputSequence.cs:3527-3540` 참조). 
3. 아웃풋 바코드 시퀀스 자체 검증은 실장비에서 (팀장님 수행).

### 계측
- 게이트 발동 시: `Log.Write(LogLevel.AboveNormal, ...)` "재시작 바코드 게이트 발동 —
  수행플래그/BarcodeConfirmed/ID" 1줄. 알람 아님.
