## 1. 목표 동작 (사용자 확정)

### 트리거·게이트 (모두 충족 시에만)

1. 자기 측 인풋 비전 **선행검사 배치 촬영이 진행 중**일 것
2. 자기 픽커가 **픽업 대기 상태**(대기점에서 허가 대기)일 것
3. **Auto + 연속 픽업(ContiSegmentedPickUp) 모드**일 것 — 일반 모드는 기존 동작 그대로
4. 신설 On/Off 스위치 On (기본 Off)

### 동작

```
촬영 배치 4개 die의 "비전 점유 X" 중 최댓값(피커 접근 방향으로 가장 가까운 값)을 찾아
→ 동적 선행 대기점 = maxBatchVisionX + FollowMove 클리어런스 산식 (+ 여유 가산 파라미터)
→ 대기 피커 X를 촬영 진행 중에 그 위치로 이동시켜 대기 (즉시 이동 — 촬영 블러 영향은 실런 확인 항목)
→ 이후 흐름 무변경: 촬영 종료 → 비전 독립 회피 → 허가 → 기존 팔로잉 진입
   (팔로잉이 훨씬 가까운 거리에서 시작되는 것이 이번 수정의 전부다)
```

- **max 기준인 이유**: 배치 내 촬영 순서와 무관하게, 비전이 배치 중 가장 피커 쪽으로 나오는 위치를 기준으로 하면 배치 내내 간격이 보장된다.
- **클리어런스는 기존 산식 재사용**: FollowMove가 쓰는 safetyGap(SafetyDistance + Input 여유, 하한 클램프 — AjinAxis.cs:533-535 기존 값) 그대로. **새 산식 발명 금지.** 비전 축↔피커 축 좌표 변환도 SharedRailX 기존 변환 재사용 (실측 예: visionTarget=388.161 ↔ pickerTarget=368.161처럼 축 간 오프셋 존재).
- 동적 대기점이 현재 고정 대기점보다 **먼 경우(후퇴가 되는 경우)에는 이동하지 않는다** (전진만 허용, 후퇴 없음).
- 배치 좌표를 얻을 수 없으면(예약 정보 부재 등) 동작하지 않고 기존 대기 유지 — fail-safe.

### 신설 파라미터 (유닛 Config, 레시피 아님 — 기존 프롬프트들과 동일 원칙)

- On/Off 스위치 (예: `PickUpDynamicWaitMode` Off/On, 기본 **Off**)
- 여유 가산 (예: `DynamicWaitExtraMarginMm`, double, 기본 0.0 — 현장 튜닝용, 클리어런스에 가산)
- 위치: `PickerPickUpMotionConfig` (PickerTransferTypes.cs:43) + PickerFrontUnit/PickerRearUnit 프로퍼티 노출 (PickerFrontUnit.cs:329-333 스타일). 설정 파일 하위호환(누락 시 기본값) 확인.

### 범위 제외 (별도 승인 필요 — 이번에 구현 금지)

- Place 복귀 X가 고정 대기점을 거치지 않고 동적 선행 대기점으로 직행하는 통합 (2위 지연 4.6s 시너지 항목) — 레포트에 제안만 기재.
- 촬영 노출 사이에만 이동하는 blur-safe 모드 — 실런에서 블러 영향 확인 후 필요 시 별도 지시.

## 3. 수정 지점 (계획 단계에서 확정)

1. **동적 대기점 산출 함수**: 촬영 배치(PreparedItems/예약 정보)에서 die별 비전 점유 X를 수집 → max → 공유레일 좌표 변환으로 피커 축 좌표화 → + FollowMove safetyGap(C3 재사용) + DynamicWaitExtraMarginMm. 배치 정보 부재/불완전 시 null 반환(동작 안 함).
2. **선행 이동 발동 지점**: 촬영 시작(선행검사 배치 개시) 시점에 게이트 4종 판정 후, 대기 픽커 X를 산출 위치로 이동 명령 (비동기, 대기 상태 유지). 발동 지점 후보: InputCameraPreInspectionCoordinator의 촬영 시작 통지 또는 PickerProcessSequence의 대기 루프 — 계획 단계에서 확정. 전진만 허용(현재 위치보다 후퇴면 스킵).
3. **targetName/존 태그**: 이동 명령에 기존 팔로잉 진입과 동일 계열의 존/의도 태그를 부여해 C7 페어 간격 분기와 C8 존 판정을 통과시킨다 (태그 누락 = -11/존 판정 불가 차단).
4. **이후 흐름 접속**: 허가 후 기존 팔로잉 진입(C2)이 새 대기점에서 자연 시작되는지 확인 — 팔로잉 시작 조건이 고정 대기점을 전제하는 코드가 있으면 현재 위치 기준으로 일반화.
5. **정리 경로**: 선행 이동 중 CycleStop/시퀀스 정지/촬영 실패 시 이동 Task 정리(join/취소), 대기 상태 일관성 유지.
6. **로그 계측 (필수)**: 발동 시 배치 maxVisionX·변환 좌표·클리어런스·산출 대기점·이동 거리, 스킵 시 사유(게이트 미충족/후퇴 방지/배치 정보 부재), 허가 시점의 실제 팔로잉 시작 거리 — 실런 1회로 효과(전진 폭·진입 시간 단축)를 확정할 수 있게.
