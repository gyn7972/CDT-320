5. 읽기 쉬운 클래스 구성
----------------------
1) AxisInitializeSafetySnapshot
   - 미리보기 시각
   - Plan에 포함된 축의 이름, Actual, Command, Moving, Servo, Alarm, HomeDone
   - 축 명령이나 상태 변경 기능은 두지 않는다.

2) AxisInitializeRouteResult
   - Step별 Phase, Lane, 현재 판정, 대기 사유
   - ReadyNow/RequiresRecheck/Disabled처럼 의미가 분명한 상태만 사용한다.
   - UI와 로그가 같은 결과를 사용한다.

3) AxisInitializeRoutePlanner
   - Step을 StepNo 순서로 정리한다.
   - CommonPreLane/InputLane/OutputLane/SharedRailPostLane을 표시한다.
   - AxisInitializeRuntime의 읽기 전용 상태와 인터락 검사만 사용한다.
   - 실제 모션과 Alarm 발생 기능을 갖지 않는다.

4) AxisInitializeSequence
   - PreviewRoute로 Planner를 호출한다.
   - 실제 전체 초기화 시작 시 미리보기 결과를 로그로 남긴다.
   - 기존 ExecuteSequenceFlowAsync 실행 순서는 그대로 유지한다.

7. 실행용 검사와 미리보기 검사의 분리
-----------------------------------
- VerifyStep: 기존과 동일하게 실패 로그와 INIT-INTERLOCK Alarm을 발생한다.
- InspectStep: 같은 규칙을 읽지만 일반적인 조건 불충족으로 INIT-INTERLOCK 실패 로그와 Alarm을 발생시키지 않는다.
- 기존 예외 진단과 Simulation 물리 IO Bypass 정보 로그는 유지한다.
- 두 경로는 하나의 VerifyStepCore를 사용하여 판정 규칙이 갈라지지 않게 한다.
