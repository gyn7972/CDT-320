CDT-320 비전 / 작업뷰 데이터 처리 통일 설계서

v2 — 실제 소스 검증 후 정정 · 2026-06-29
v2 정정 사유. v1은 "핸들러 sim이 InspectionResultStore를 우회한다 → 단일 진입점 Publish로 묶자"고 했으나, 실제 소스 확인 결과 핸들러(QMC.CDT-320)와 비전(QMC.Vision)은 별도 프로세스이고 핸들러는 QMC.Common만 참조하여 비전 스토어/뷰어에 접근 자체가 불가능하다. 따라서 v1의 "핸들러→Publish→스토어" 경로는 성립하지 않는다. 아래는 검증된 구조 기준의 정정안이다.

2. 비전 작업뷰의 데이터 경로는 이미 통일돼 있다

비전 앱 내부에서는 실제든 sim이든 동일한 경로를 탄다. 차이는 검사기 백엔드(Cognex vs Sim)뿐이다.

핸들러 ──TCP INSPECT──▶ 비전 앱 │ VisionCommandCore.InspectOnImage() │ (검사기 = Cognex 또는 Sim fallback) ├─▶ InspectionResultStore.Record() ← 항상 └─▶ Changed 이벤트 │ InspectionViewerControl 갱신 ✔
  • 비전 앱 자체 시퀀서 보유: BinVisionSequence / WaferVisionSequence / Front·RearSideVisionSequence
  • Sim 백엔드: SimBackend / SimInspector (VisionFactory가 카메라 미설치 시 자동 fallback)
  • 실제·Sim 모두 VisionCommandCore를 거쳐 같은 스토어를 채운다 → 뷰어 기준 sim=실제 이미 보장

3. 그럼 왜 "sim에서 뷰어가 비어 보였나" — 원인은 설정

핸들러의 합성 결과 함수 SimulateBottomResult() / SimulateSideResult()는 오직 IsVisionBypassed() 한 곳에서만 호출된다. 그리고

IsVisionBypassed() == !AppSettings.UseVision
설정핸들러 동작비전 뷰어
UseVision = true + 모션 SimulationMode그래도 TCP로 비전에 요청 전송 (합성 안 함)결과 표시됨 (sim=실제 경로)
UseVision = false비전 미접속 + SimulateBottomResult() 합성 → Material에만 기록비어 있음 (당연 — 비전 끔)

※ ShouldUseSimulatedBottomVision()은 로그 문구(DescribeBottomVisionRuntimeMode) 생성에만 쓰이며 실제 게이트가 아니다. 게이트는 UseVision 단일.

결론. 뷰어 기준 데이터 통일은 이미 구현돼 있다. sim 테스트에서 비전 작업뷰를 채우려면 코드 수정이 아니라 운영 설정이면 된다 — ① UseVision = true 로 두고(모션은 SimulationMode 자유), ② 비전 앱을 Sim 백엔드로 함께 실행. 그러면 핸들러→TCP→비전(Sim)→VisionCommandCore→스토어→뷰어로, 실제와 완전히 같은 경로를 탄다. UseVision=false는 "비전 자체를 쓰지 않음"이므로 그 모드에서 뷰어가 비는 것은 정상이다.

5. 남은 통일 작업 (선택 · 뷰어와 무관)

아래는 위 결론(뷰어는 이미 통일)과 별개로, 모델·코드 정합성 차원의 개선이다. 필요 시 진행.

5-1. 크로스앱 모델 정합 중

핸들러 BottomInspectionResult / SideInspectionResult(타입 프로퍼티, Side 1채널)와 비전 Item(딕셔너리, Side 4채널)이 다르다. QMC.Common에 공유 VisionResult DTO를 두고 양쪽이 같은 모양을 쓰면 TCP 양쪽 직렬화·해석이 일관된다. 두 앱이 함께 참조 가능한 곳은 QMC.Common뿐이므로 여기가 유일한 위치.

5-2. 비전 앱 내부 스토어 정리 하

ModuleResultStore(OK/NG·마크)와 InspectionResultStore(측정값) 역할 중복. OperationPage의 폴링(250ms)을 Changed 이벤트 구독으로 전환. 비전 앱 단독 작업이라 핸들러 영향 없음.

5-3. 핸들러 합성결과 형상 통일 하

핸들러 SimulateBottomResult는 offset+OK만 만든다(Width/Chipping 없음). UseVision=false 단독 테스트에서 핸들러측 Material 표시 일관성이 필요하면 5-1의 공유 DTO로 채운다. 뷰어와는 무관.

6. 대원칙 (고정)

  • 동작은 따로, 데이터는 통일. Bottom/Side/Bin은 각 모듈 요청으로 독립 실행. 통일 대상은 결과 양식·저장·표시 경로뿐.
  • 뷰어 데이터는 단일 경로. 비전 작업뷰는 항상 VisionCommandCore → InspectionResultStore → Changed로만 채운다. sim=실제 차이는 검사기 백엔드뿐.
  • UseVision 의미 고정. true=비전 사용(실제/Sim 무관), false=비전 미사용. sim 테스트는 true로 운영.
  • 크로스앱 모델은 QMC.Common 공유 DTO 하나로. 뷰별 전용 DTO 신설 금지(어댑터 변환만).
  • (AGENTS.md) 이동 완료 확인 등 시퀀스 안전규칙은 sim에서도 생략 금지.
