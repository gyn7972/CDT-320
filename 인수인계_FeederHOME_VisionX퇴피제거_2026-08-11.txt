[2] 왜 바꿨는가 (배경)

  Step 180 : InputVisionX 를 MEL(-) 하드리밋까지 주행 -> 5mm 이탈 -> InputFeederY HOME
  Step 260 : OutputVisionX 를 PEL(+) 하드리밋까지 주행 -> 5mm 이탈 -> OutputFeederY HOME

  실행 전에 "이번 전체 초기화 실행 안에서" 공통 Z + PickerY 14축의 HOME 완료를 요구했다.

2-3. 근본 원인 (반드시 이해할 것)
  선행조건 검사는 AxisInitializeRunState.IsAxisHomed() 기반이었다.
  이 함수는 단순 조회가 아니라 다음 3단으로 판정한다.

    (1) axis.UpdateStatus()  <- 호출 시점에 보드 상태 재조회
    (2) _homedAxisNames 에 축 이름이 없으면 false
    (3) axis.IsAlarm 이거나 !axis.IsHomeDone 이면 목록에서 제거하고 false

  그리고 _homedAxisNames 는 BeginRun() 에서 생성되고 EndRun() 에서 null 로 버려진다.
  문제는 BeginRun/EndRun 이 감기는 단위가 두 가지라는 것이다.

    - 전체 초기화        : BeginRun -> 전체 Step -> EndRun   (목록 유지됨)
    - 개별축 HOME 버튼   : BeginRun -> 축 1개 -> EndRun      (매번 목록 폐기!)
      (AxisInitializeExecutor.ExecuteSingleAxisHomeAsync)

  따라서 작업자가 개별축 HOME 으로 하나씩 복구하는 동안에는
  14축 조건이 절대 충족될 수 없고, Step 180/260 은 영구 차단된다.
  현장에서 "홈 잡았다고 표시되는데 왜 막히냐"고 한 것이 정확히 이 현상이다.
  (Servo ON / 알람 없음 / HomeEnd 표시 상태에서도 (2)번에서 걸린다)

2-4. 팀장님 결정 (2026-08-11)
  - 카메라 퇴피 동작을 Input/Output 양쪽 다 제거한다.
  - FeederY HOME 안전은 Feeder Avoid Dog 센서로 확인한다.
  - Dog OFF 면 그냥 실패 처리한다. 작업자가 수동으로 Feeder 를 Avoid 로 뺀 뒤 재시도.
    (카메라를 자동으로 움직이지 않는다)

[8] 남은 이슈 / 판단 필요 사항
--------------------------------------------------------------------------------
8-1. 이번 변경으로 해소되지 않는 별개 장애 3건 (이번 작업 범위 밖)

  (1) EjectPinZ HOME 시작 차단
      "Servo ON 및 Axis Alarm OFF 상태가 필요합니다. servo=OFF ...
       자동 AlarmReset/ServoOn은 수행하지 않습니다."
      초기화 플랜에 EjectPinZ Servo ON 경로가 없어 사전 수동 Servo ON 이 필요하다.
      게다가 AjinAxis.ServoOnCore 는 AlarmManager.HasActive 이면 조용히 무시하므로
      반드시 [알람 리셋] -> [EjectPinZ Servo ON] -> [초기화] 순서로 해야 한다.

  (2) 27개 축 동시 "Servo alarm 0x0001" (앱 시작 시)
      이 0x0001 은 드라이브 고유 코드가 아니라 "보드가 amp fault 를 보고했다"는
      소프트웨어 기본값이다. (AjinAxis.cs 의 AlarmCode = AlarmCode == 0 ? 1u : AlarmCode)
      27축 동시 발생이므로 개별 서보 고장이 아니라 EMG / 안전회로 / 드라이브 전원
      계열 공통 원인을 봐야 한다.
      ★ fault 가 참인 동안은 _homeDoneLatched 가 계속 풀려서 어떤 축도 홈 상태를
        유지할 수 없다. (AjinAxis.UpdateStatus: !IsServoOn || fault || (IsAlarm && !limitAlarm))
      같은 시각 "TOP-DOOR> Door check inputs were not found." 도 함께 나온다.

  (3) FrontPickerZ0 (AxisNo 12) 소프트리밋 값 불일치
      알람: Soft limit reached (positive). Position=11.19, Limit=1, AxisNo=12
      런타임 SoftLimitPlus = 1 인데 Setup\FrontPickerZ0.json 은 20 (Stroke 25),
      파일 수정일이 6/20 이다. PickerZ 스트로크 25mm 에 상한 1mm 는 정상 티칭값으로
      보기 어렵다.
      ★ Setup 파일은 앱 종료 시 런타임 값으로 덮어써지므로, 확인/수정은 반드시
        앱을 종료한 상태에서 해야 한다.
      AxisNo 9 도 같은 양상 (Position=-52.334, Limit=-9).

8-2. Step 180 / 260 의 플랜 레벨 HomeDone 인터락은 그대로 남아 있다

  AxisInitializeSequence.cs
    :252~255  Step 180 -> FrontPickerY, RearPickerY,
                          FrontPickerZ0~Z3, RearPickerZ0~Z3  HomeDone 요구

  즉 PickerZ 8축 + PickerY 2축 HOME 이 먼저 성공해야 Step 180/260 이 실행된다.
