1. F3 이동 명령 계약

적용 범위는 InputCamera 선행검사에서 사용하는 다음 6축으로 한정한다.

- VisionX
- NeedleX
- WaferY
- WaferT
- WaferExpandingZ, 즉 ExpanderZ
- EjectPinZ

NeedleZ는 현재 InputCamera 선행검사 공정 중 이동하지 않으므로 제외한다.

InputVisionXPrePositionCoordinator는 별도 PositionOverride 최적화 경로이므로 이번 변경에서 제외한다.

각 대상 축에 대해 다음 조건을 모두 만족할 때만 이동 명령을 생략한다.

- ActualPosition의 invariant F3 값이 Target의 invariant F3 값과 동일
- CommandPosition의 invariant F3 값이 Target의 invariant F3 값과 동일
- Servo ON
- Alarm OFF
- Moving OFF
- InPosition ON
- 기존 장비의 Actual/Command tolerance 완료 조건도 만족

F3 비교는 CultureInfo.InvariantCulture 기준으로 일관되게 수행한다.

다음 중 하나라도 만족하지 않으면 이동 명령을 생략하면 안 된다.

- Actual F3 불일치
- Command F3 불일치
- Servo OFF
- Alarm ON
- Moving ON
- InPosition OFF
- 기존 tolerance 완료 조건 불만족
- 축 상태 갱신 실패 또는 상태 확인 예외

명령을 생략할 수 없는 경우 해당 이동 명령 하나만 forceMove=true로 실행한다.

forceMove는 기존 Unit/BaseAxis 내부의 위치 동일 판단만 우회해야 한다.

다음 검증은 그대로 유지해야 한다.

- MotionGuard
- SharedRail
- WorkArea
- Material
- Servo/Alarm
- InPosition/tolerance
- 소프트리밋 및 기존 장비 이동 안전 조건

기존 AxisMoveWaiter.CanSkipMoveCommandAtTarget()의 의미는 변경하지 않는다.

권장 방식:
- AxisMoveWaiter에 별도의 opt-in F3 전용 강한 판정 메서드를 추가한다.
- 기존 메서드 구현과 호출 의미는 변경하지 않는다.
- F3 판정 전 가능한 경우 axis.UpdateStatus()로 최신 상태를 반영한다.
- UpdateStatus 실패 또는 예외 발생 시 false를 반환하여 명령 생략을 금지한다.

2. forceMove 전달

InputStageUnit에는 이미 다음 형태의 overload가 있는지 현재 코드에서 재확인한다.

MoveInputStageAxis(
    WaferStageAxis axis,
    double targetPos,
    bool bFine,
    bool forceMove)

기존 overload가 존재하면 재사용한다.

InputCamera 선행검사의 6축 호출에서만 F3 판정 결과에 따라 forceMove를 전달한다.

WaferY가 PickerInputStageMoveHelper를 경유하여 forceMove를 전달하지 못한다면:

- optional bool forceMove = false 인자를 최소 범위로 추가
- 기존 호출자는 기본값 false를 유지
- 이번 선행검사 호출만 필요한 경우 true를 전달

3. NeedleX와 WaferY 순차 이동 유지

현재 NeedleX와 WaferY는 TryResolveNeedleWorkPointMoveOrder() 결과에 따라 순차 이동하는 것으로 파악된다.

현재 소스에서 다시 검증한 뒤 다음을 지킨다.

- NeedleX와 WaferY를 Task.WhenAll 등으로 동시에 이동하지 않는다.
- NeedleX → WaferY 또는 WaferY → NeedleX 순차 await 구조를 유지한다.
- 기존 WorkArea 기반 이동 순서 계산을 유지한다.
- 현재 허용된 VisionX + NeedleX 이동 구조는 이번 작업에서 변경하지 않는다.

4. 상위 중복 완료 대기 제거

InputStageUnit.MoveInputStageAxis()가 내부에서 다음 동작을 모두 수행하는지 현재 코드에서 다시 확인한다.

- 실제 이동 명령
- 이동 결과 확인
- WaitInputStageAxisInPositionResult() 또는 동등한 InPosition/tolerance 완료 대기

위 조건이 확인된 경로에서만 상위의 중복 async wait를 제거한다.

InputDieVisionPrepareSequence에서 확인할 대상:

- WaferExpandingZ 이동 후 상위 중복 wait
- WaferT 이동 후 상위 중복 wait
- EjectPinZ 이동 후 상위 중복 wait
- VisionX 이동 후 상위 중복 wait
- NeedleX 이동 후 상위 중복 wait
- WaferY 이동 후 상위 중복 wait
- 사용되지 않는 VisionX helper에 같은 중복 wait가 있으면 안전하게 정리

중요:
- 이동 명령 자체는 제거하지 않는다.
- Unit 내부 완료 대기는 제거하지 않는다.
- 이동 후 마지막 CheckInputStageAxisInPosition 또는 동등한 축 상태 검사는 유지한다.
- WaferT의 early return 때문에 마지막 상태 검사가 빠지지 않도록 확인한다.
- Servo/Alarm/Moving/InPosition/tolerance 최종 확인을 유지한다.

InputCameraMarkInspectionSequence의 InputVisionX Avoid도 같은 원칙으로 처리한다.

- stage.MoveInputStageAxis(VisionX, Avoid, ...)가 내부 완료 대기까지 수행한다면 상위의 중복 WaitInputStageAxisInPosition만 제거
- 마지막 stage.IsVisionXInAvoidPosition() 실제 확인은 반드시 유지
- F3 강한 생략 조건이 불충족이면 Avoid 명령도 forceMove=true로 발행
- Permission, lease, zone, RESULT 병렬 처리 구조는 변경하지 않는다
