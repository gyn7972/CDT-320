기능 7. 카세트 LOT-ID 등록 및 Data 처리 강화

- 작업정보 → 인풋카세트 화면에서 현재 생산 LOT-ID를 등록/확인한다.
- 작업정보 → 아웃풋카세트 화면에서도 같은 생산 LOT-ID를 등록/확인한다.
- Input1/Input2/Good1/Good2/NG1이 서로 다른 LOT을 따로 갖는 구조가 아니라,
  한 번 등록한 “현재 생산 LOT” 하나를 공통으로 사용한다.
- Input Cassette Mapping으로 생성되는 Wafer Data에 등록 LOT-ID가 들어간다.
- Input Cassette 화면에서 Material Data를 강제로 생성할 때도
  등록된 LOT-ID가 정확히 동일하게 들어간다.
- Output Cassette의 Mapping/강제 생성/반환 Data도 같은 LOT-ID를 유지한다.
- Auto, Vision, CSV, TactTime, Material Snapshot에서 사용하는 LOT-ID가
  서로 달라지지 않게 한다.
- 미등록, 다중 LOT 불일치, 처리 중 LOT 변경은 조용히 보정하지 않고 차단한다.
- 등록한 LOT-ID는 프로그램 재시작 및 Material Snapshot 복구 후에도 유지한다.

기능 8. 카세트 맵핑 전/후 슬롯 수동 이동

- 작업정보 → 인풋카세트/아웃풋카세트 화면에
  “맵핑 전”과 “맵핑 후” 이동 기준을 명확히 나눈다.
- PREV/NEXT와 슬롯 GUI 더블클릭이 같은 이동 기준을 사용한다.
- 맵핑 전:
  각 카세트 역할의 기구 티칭 FirstPosition을 기준으로 SlotPitch만큼 이동한다.
- 맵핑 후:
  해당 역할/슬롯의 현재 Wafer에 저장된 CurrentCassetteSlotPosition으로 이동한다.
- 슬롯 상태 GUI를 더블클릭하면 역할, 슬롯, 이동 기준, 목표 위치를 보여주고
  “해당 위치로 이동하시겠습니까?”를 OK/Cancel로 한 번만 묻는다.
- OK에서만 기존 수동 Action Scope와 기존 인터락을 통과해 이동한다.
- Cancel에서는 모션 및 Material Data 변경이 없어야 한다.
- 이 수동 화면 기능이 Auto Mapping/Loading/Unloading의 위치 계산과
  기존 인터락을 변경해서는 안 된다.

2. 현재 코드에서 확인된 구조적 사실
======================================================================

계획서를 작성할 때 아래 사실을 현재 코드에서 다시 확인한다.
함수명이나 위치가 달라졌으면 최신 코드 기준으로 정정하고 근거를 남긴다.

2.1 LOT-ID 데이터는 이미 있으나 등록 정본이 없다
---------------------------------------------------

현재 LOT 관련 값은 다음 위치에 분산되어 있다.

- RecipeProject.LotId
- MaterialSnapshot.LotId
- CassetteMaterial.CassetteLotId
- WaferMaterial.CassetteLotId
- LotStorage.ActiveLot.LotID

관련 파일:

- QMC.CDT-320\Equipment\Recipes\RecipeStore.cs
- QMC.CDT-320\Equipment\Materials\MaterialModel.cs
- QMC.CDT-320\Equipment\Materials\MaterialStateService.cs
- QMC.CDT-320\Equipment\Materials\MaterialSnapshotStore.cs
- QMC.CDT-320\Equipment\Lots\LotStorage.cs

MaterialSnapshot.LotId, CassetteMaterial.CassetteLotId,
WaferMaterial.CassetteLotId 필드는 이미 DataMember로 저장된다.
새 LOT 문자열 필드를 중복 추가하지 않는다.

현재 활성 Auto 진입점은 아래 경로다.

WorkTab.Start
→ MachineController.StartAsync
→ MachineController.StartSequenceAsync(SequenceRunOptions.ProcessAuto)
→ AutoSequenceCoordinator

Legacy CycleRunAsync 영역의 timestamp LOT 생성은 현재 활성 Auto의 기준이 아니다.
이번 기능 때문에 Legacy CycleRunAsync를 수정하거나 새 Auto에 다시 연결하지 않는다.

2.2 현재 Mapping의 LOT 결정 방식
--------------------------------

InputCassetteSequenceBase.RegisterMappingResult와
OutputCassetteSequenceBase.RegisterMappingResult는
LotStorage.ActiveLot이 있으면 그 값을 넘기고, 없으면 빈 문자열을 넘긴다.

MaterialStateService.ResolveOrCreateCassetteLotId 계열은
요청값/State/Cassette/Wafer의 non-empty 후보를 모아서:

- 후보 1개: 그 값을 사용
- 후보 2개 이상: 불일치 예외
- 후보 0개: AUTOLOT-* 임시 LOT 자동 생성

현재는 운영자가 등록하지 않아도 생산 Mapping에서 AUTOLOT이 생길 수 있다.
또한 잔존 LOT 하나만 달라도 Mapping이 실패할 수 있다.

Mapping 성공 시 UpdateCassetteMapping이 State, Cassette, 생성 Wafer에
같은 LOT을 복제하고, 같은 Wafer 객체가 Feeder/Stage/Picker/Output으로
이동하므로 정상 경로에서는 Wafer LOT이 유지된다.

2.3 현재 LOT 편집/강제 생성 위험
--------------------------------

InputCassettePage는 선택 슬롯 Detail Grid의 Lot ID를
일반 Wafer 필드처럼 편집할 수 있다.

UpdateWaferFieldInMappedCassette의 CassetteLotId 분기는
선택 Wafer와 선택 Cassette 위주로 값을 바꾸므로,
State와 다른 Cassette/Wafer 사이에 LOT 불일치를 만들 수 있다.

InputCassettePage의 강제 Material Data 생성은:

GetOrCreateWaferInMappedCassette(role, slot, "")

처럼 빈 LOT을 넘겨 암묵 후보 해석에 의존한다.
또한 슬롯 고정 Wafer ID를 재사용하면서 새 physical wafer에 필요한
이전 Align/Mapping/Review/Die 진행 상태 초기화가 누락될 가능성이 있다.

OutputCassettePage의 강제 Material Data 생성도
선택 Cassette의 LOT만 읽어서 PutWaferInCassette에 넘기며,
현재 등록 LOT 정본과의 일치 검증이 없다.

기존 LotIdInputDialog는 있으나 현재 호출처가 없고,
초기값/빈값/금지문자/길이 검증이 부족하다.
새 Dialog를 중복 생성하기 전에 이 Dialog의 재사용/보강을 우선 검토한다.

2.4 Snapshot 저장 시 LOT 자동 부활 위험
---------------------------------------

MaterialStateService.NormalizeSnapshotHeader는 State.LotId가 비어 있으면
첫 번째 non-empty Cassette 또는 Wafer LOT을 골라 State.LotId에 넣는다.

이 방식은 여러 LOT이 섞여 있어도 첫 번째 값 하나를 조용히 선택할 수 있고,
사용자가 LOT을 비운 뒤 잔존 LOT이 다시 살아나는 원인이 될 수 있다.

계획에는 반드시 다음 정책이 들어가야 한다.

- LOT 후보 0개: 공백/미등록
- 고유 LOT 후보 1개: 명시된 호환 정책에 따라 복구 가능
- 고유 LOT 후보 2개 이상: 첫 값 선택 금지, Recovery Required로 차단

2.5 활성 Auto의 LOT 사용
------------------------

활성 Auto의 StartSequenceAsync는 LotStorage.OpenLot을 호출하지 않는다.
생산 통계/TactTime은 ActiveLot → MaterialSnapshot.LotId → timestamp 순으로
LOT을 해석하고, Vision은 Wafer → MaterialSnapshot → Recipe 순으로 해석한다.

따라서 정본이 없으면 Tact/Vision/CSV 파일 이름 또는 내용이 서로 달라질 수 있다.
계획에서는 활성 Auto 시작 전 등록 LOT과 전체 LOT 일관성을 검증해야 한다.
또한 활성 Auto에서 ActiveLot이 계속 null이면
LotStorage.ActiveLot?.RecordDie 계열 통계가 누락될 수 있으므로,
등록 LOT과 동일한 ActiveLot 통계 Session의 Open/Resume/Complete/Abort 수명도
활성 Auto 경로 기준으로 계획해야 한다.

RecipeProject.LotId는 초기 제안값 또는 구버전 호환값일 수 있으나,
운영자가 명시 등록한 현재 생산 LOT의 정본으로 자동 확정하지 않는다.
LOT 등록 UI가 Recipe 파일을 수정하지 않게 한다.

2.6 현재 Input 슬롯 이동
------------------------

InputCassettePage:

btnPrev/btnNext
→ MoveSlotAsync
→ MoveSpecificSlotAsync
→ MaterialStateService.TryGetCassetteSlotPosition
→ InputCassetteUnit.MoveWaferLifterZ

TryGetCassetteSlotPosition은 Cassette가 Mapping 완료 상태이고,
해당 슬롯에 Wafer가 있으며,
Wafer.CurrentCassetteSlotPosition이 있어야 성공한다.

따라서 현재 Input 화면에는 “맵핑 전 FirstPosition + Pitch” 이동이 없다.

2.7 현재 Output 슬롯 이동
-------------------------

OutputCassettePage:

btnPrev/btnNext 또는 우클릭 MOVE
→ OutputCassetteSequence.RunMoveSlotAsync
→ OutputCassetteMoveSlotSequence
→ OutputCassetteUnit.CalculateBinCassetteSlotTargetPosition

현재 Output 계산은 Mapping 실측 배열이 있으면 실측을 사용하고,
없으면 명목 위치로 자동 폴백한다.
따라서 화면에서 맵핑 전/후 기준을 명시적으로 선택할 수 없다.

OutputCassettePage의 수동 MoveSlot이 SequenceStartMode.Resume을 사용하면,
이전 Resume Step에 role/slot/mode fingerprint가 없는 상태에서
새 요청이 과거 상태를 재개할 수 있다.
새 수동 단발 이동은 Fresh/Restart 기준으로 계획한다.
Auto/기존 공정의 Resume 정책은 이번 기능으로 변경하지 않는다.

2.8 맵핑 전 위치 공식
---------------------

현재 slotIndex=0은 UI의 SLOT 01이며 각 Cassette의 최상단 슬롯이다.
위에서 아래로 slotIndex가 증가하고 축 목표도 SlotPitch만큼 증가한다.

맵핑 전 목표 공식:

Target = FirstPosition + (SlotPitch × slotIndex)

역할별 FirstPosition:

- Input1: InputCassetteRecipe.Level1FirstSlotPosition
- Input2: InputCassetteRecipe.Level2FirstSlotPosition
- Good1: OutputCassetteRecipe.GoodFirstSlotPosition
- Good2: OutputCassetteRecipe.Good2FirstSlotPosition
- Ng1: OutputCassetteRecipe.NGFirstSlotPosition

맵핑 전 모드는 과거 Mapping 배열, 현재 Wafer 위치,
다른 레벨 FirstPosition fallback을 사용하지 않는다.

FirstPosition이 미티칭 상태이거나 SlotPitch가 유효하지 않으면
목표를 임의 생성하지 말고 이동을 차단한다.

2.9 맵핑 후 위치 기준
---------------------

Mapping 등록 시 Wafer에 저장되는 CurrentCassetteSlotPosition은
Raw 센서 검출 위치가 아니라 최종 Loading 위치다.

Input:
실측 검출 위치 + 해당 Level Loading Offset

Output:
실측 검출 위치 + 해당 Zone Loading Offset

맵핑 후 모드는 반드시 아래 조건을 모두 만족해야 한다.

- 대상 Cassette가 현재 Mapping 완료 상태
- 선택 Role/Slot과 슬롯 Wafer/현재 위치가 일치
- Wafer.CurrentCassetteSlotPosition이 유효
- 목표가 축 이동 범위 안

하나라도 만족하지 않으면 이동을 차단한다.
FirstPosition+Pitch 또는 Recipe Mapping 배열로 자동 폴백하지 않는다.

사용자 요구가 “현재 웨이퍼에 저장된 포지션 값”이므로,
Wafer가 없거나 저장 위치가 없는 빈 슬롯은 맵핑 후 이동을 차단한다.
이번 범위에서 빈 슬롯용 별도 위치 필드를 MaterialModel에 추가하지 않는다.

MaterialSnapshotStore는 NaN/Infinity 위치를 -1.0으로 정규화하는 경로가 있다.
NaN만 검사하면 복구 후 -1.0을 정상 목표로 오인할 수 있다.
맵핑 후 위치 유효성은 NaN, Infinity, legacy -1 sentinel,
축 Soft Limit 범위를 함께 검사해야 한다.

3. 계획서 작성 시 확정할 설계 원칙

3.1 LOT-ID 정본
---------------

- 현재 생산 LOT의 정본은 MaterialSnapshot.LotId로 한다.
- Input/Output 두 화면은 같은 값을 표시하고 같은 중앙 등록 API를 호출한다.
- Cassette/Wafer의 CassetteLotId는 정본의 전파/추적 사본이다.
- RecipeProject.LotId는 운영 등록값을 덮어쓰지 않는다.
- LotStorage.ActiveLot이 존재하면 등록 LOT과 일치하는지 검증한다.
- Legacy CycleRunAsync는 수정하지 않는다.

3.2 명시 등록 상태
-----------------

Recipe 초기값, Snapshot 복구값, 자동 생성값과
운영자가 등록한 값을 구분할 수 있어야 한다.

계획에서 아래 메타데이터 추가 여부를 검토하고 결정한다.

- IsLotIdRegistered
- LotIdRegisteredAt
- LotIdRegisteredBy
- LotIdRegistrationSource

구 Snapshot에는 이 필드가 없으므로 기본값/복구 호환 정책을 명시한다.

3.3 중앙 등록 API
----------------

예시:

- RegisterCurrentLotId(...)
- TryGetRegisteredLotId(...)
- ValidateCurrentLotConsistency(...)

실제 이름은 기존 명명 규칙에 맞춰 계획서에서 확정한다.

등록 API는 다음 책임을 갖는다.

- trim 및 대소문자 비교 정책
- 공백, 제어문자, CR/LF, 파일명 금지문자, 길이 검증
- 문자열 무음 자르기 금지
- 같은 LOT 재등록은 멱등 성공
- State/Cassette/대상 Wafer를 하나의 lock에서 원자적으로 일치
- 실패 시 부분 변경 금지
- NotifyAndSave 및 즉시 저장 완료 확인
- 사용자/화면/시각/이전값/새값 로그
- 읽기 전용 조회 API 제공

허용 문자와 최대 길이는 Vision 프로토콜, CSV/파일명 사용처를
현재 코드에서 조사한 뒤 계획서에 정확히 확정한다.

3.4 LOT 변경 차단/안전 재바인딩
------------------------------

다른 LOT으로 변경은 다음 상태에서 차단한다.

- Auto 또는 Manual Sequence 실행 중
- 수동 Motion 실행 중
- Cassette 밖 Feeder/Stage/Picker 등에 Material이 존재
- Pick/Inspection/Die 진행 또는 완료 Data가 존재
- 다른 LOT의 ActiveLot이 Running
- State/Cassette/Wafer에 두 개 이상의 고유 LOT이 존재

동일 LOT 재등록은 허용한다.

기존 AUTOLOT 또는 Recipe 초기값을 실제 LOT으로 바꾸는 경우,
모든 Material이 아직 Cassette에 있고 공정 이력이 전혀 없는 상태에서만
원자적 안전 재바인딩을 허용할지 계획서에서 명확히 정한다.
조용한 전체 덮어쓰기는 금지한다.

LOT을 빈 문자열로 직접 편집하는 기능은 제공하지 않는다.
LOT 해제/교체는 Material 초기화/Recovery 절차와 연결한다.

3.5 생산 경로의 미등록 처리
---------------------------

Production Auto, 실제 Manual Mapping, 강제 Material Data 생성은
등록 LOT이 없으면 Fail-Closed한다.

AUTOLOT-* 자동 생성은 명시적인 Simulation/Process Test Data에만 허용한다.
Test LOT이 등록된 Production LOT을 조용히 덮어쓰면 안 된다.

활성 Auto 시작 경로에서 Tact recorder 생성과 통계 시작 전에:

- 등록 LOT 존재
- State/Cassette/Wafer LOT 일관성
- ActiveLot이 없으면 등록 LOT과 같은 ID의 통계 Session Open/Resume
- ActiveLot이 있으면 동일 LOT인지 확인

을 검증한다.

Cycle Stop/재개 가능 Stop/Alarm에서는 같은 ActiveLot을 유지하고,
정상 Wafer 작업 완료에서 Completed,
재개를 포기한 명시적 종료에서만 Aborted가 되도록 수명을 구분한다.
이 변경은 활성 StartSequenceAsync 경로에만 적용하고
Legacy CycleRunAsync의 LOT 수명 코드는 수정하지 않는다.

3.6 Input 강제 생성
-------------------

InputCassettePage의 빈 문자열 LOT 전달을 제거하고,
중앙 등록 LOT을 명시적으로 적용하는 Domain API를 사용한다.

새 physical wafer를 강제로 생성하는 경우:

- 이전 Wafer 객체의 Align/Theta/Die Mapping/Review 승인
- Pick 예약/진행
- Die 및 Inspection 결과

가 새 제품에 상속되지 않게 한다.

기존 정상 Mapping의 신규 physical wafer 초기화 정책과 같은 중앙 Helper를
재사용하거나 동등한 불변식을 보장한다.
UI가 여러 Material 필드를 직접 수정하지 않는다.

3.7 수동 슬롯 이동 모드
----------------------

명시적 enum/값 객체를 사용한다.

예시:

- BeforeMappingTeaching
- AfterMappingStoredWafer

이 모드는 WorkInfo 수동 화면 상태일 뿐 Recipe/Material에 저장하지 않는다.
Auto Mapping/Load/Unload 계산에는 전달하지 않는다.

두 Page의 PREV/NEXT, 우클릭 MOVE, 더블클릭 MOVE는
하나의 공통 Target Resolver 규칙과 하나의 페이지 이동 실행 경로를 사용한다.
UI 이벤트별로 계산식을 복사하지 않는다.

3.8 모션 실행 경로
-----------------

Target Resolver와 Motion 실행을 분리한다.

UI
→ Role/Slot/Mode 선택
→ 중앙 Resolver가 Target/Source/실패 사유 반환
→ 확인
→ 기존 ManualActionScope
→ 기존 Unit/Sequence 이동 및 인터락
→ 완료 검증
→ 결과 로그

Input은 현재 직접 Unit 이동 경로보다 안전 조건이 약해지지 않게 하고,
필요하면 InputCassetteMoveSlotSequence 같은 단일 수동 Sequence를 계획한다.

Output은 기존 OutputCassetteMoveSlotSequence의:

- 대상 Cassette 감지
- Feeder Avoid
- Lifter 이동 준비
- MotionGuard
- 돌출 센서 이동 전/이동 중 감시
- STOP/Cancellation

를 유지한다.

수동 Page의 새로운 요청은 Fresh/Restart로 시작한다.
기존 Auto 또는 공정 Resume 동작은 변경하지 않는다.

축에 새 raw MoveAbsoluteAsync 우회 경로를 만들지 않는다.
이번 기능에서 AjinAxis의 전역 Actual/INP 완료 정책을 함께 수정하지 않는다.
현재 프로젝트의 확정된 공통 모션 완료 정책을 사용하고,
시퀀스 레벨 목표 도달 검증을 계획서에 명시한다.

3.9 더블클릭 확인
----------------

슬롯 번호와 상태 영역 모두 더블클릭을 지원한다.

확인창 예시:

[INPUT 2단 / SLOT 03]
[맵핑 후 / Wafer 저장 위치 / 123.456 mm]

해당 위치로 이동하시겠습니까?

버튼은 OK/Cancel이다.

- OK: PREV/NEXT와 같은 이동 함수 호출
- Cancel: Motion 명령 0건, Material 변경 0건
- 확인창은 정확히 한 번
- 기존 RunMotionAction의 Yes/No 창과 이중 표시 금지
- 중복 더블클릭/연타 시 두 번째 이동 시작 금지

======================================================================
4. 상세 계획서
======================================================================

아래 순서로 계획서를 작성한다.
각 단계마다 대상 파일, 대상 클래스/함수, 현재 역할, 변경 목적,
변경 후 호출 흐름, 보존 조건, 위험, 검증 방법을 적는다.

P0. 기준 상태와 변경 보호
------------------------

- 저장소/브랜치/dirty worktree를 기록한다.
- 향후 수정 후보 파일과 기존 변경의 중첩을 표로 만든다.
- 활성 Auto와 Legacy CycleRunAsync 경계를 다시 확인한다.
- Legacy 영역, 기존 Auto Load/Unload, 기존 인터락의 보호 기준을 정한다.

P1. LOT-ID 정본 및 등록 상태 모델
--------------------------------

- MaterialSnapshot.LotId를 현재 생산 LOT 정본으로 확정한다.
- 등록 여부/시각/사용자/출처 메타데이터 필요성을 결정한다.
- 구 Snapshot 역호환 및 Recipe 초기값의 “미등록 제안값” 정책을 정의한다.
- LOT 문자열 정규화, 비교, 문자, 길이 규칙을 확정한다.

P2. 중앙 LOT 등록/검증 Service
-----------------------------

- MaterialStateService의 원자적 등록/조회/일관성 검사 API를 설계한다.
- 동일 LOT 재등록, 신규 등록, 안전 재바인딩, 변경 차단을 구분한다.
- State/Cassette/Wafer 갱신 범위와 실패 시 rollback/부분 변경 방지를 정의한다.
- Snapshot 즉시 저장 및 실패 보고 정책을 정의한다.
- 다중 LOT Snapshot을 첫 값으로 선택하지 않는 Recovery 정책을 정의한다.

P3. Input/Output Cassette LOT UI
-------------------------------

- 두 Page에 같은 현재 LOT, 등록 상태, 등록 시각/사용자를 표시한다.
- REGISTER/CHANGE 동작을 같은 중앙 API에 연결한다.
- 기존 LotIdInputDialog 재사용/보강 계획을 작성한다.
- Input Detail Grid의 CassetteLotId 개별 편집을 제거/비활성화한다.
- Output Page도 동일한 조회/등록 UX를 사용한다.
- Auto/Sequence/Motion 중 버튼 비활성 및 Service 최종 차단을 모두 계획한다.
- Designer 변경은 *.Designer.cs InitializeComponent 안에서 처리한다.

P4. Mapping 및 강제 Material 생성 LOT 전파
------------------------------------------

- Input/Output Mapping이 LotStorage.ActiveLot을 직접 정본으로 사용하지 않고
  중앙 등록 LOT을 받도록 한다.
- 미등록 Production Mapping은 시작 전에 차단한다.
- Input 강제 생성은 등록 LOT을 명시 적용한다.
- 새 physical wafer가 이전 처리 상태를 상속하지 않게 한다.
- Output 강제 생성도 동일 정본과 유효 저장 위치를 사용하게 한다.
- Mapping/생성/이송/복귀 전 구간의 State/Cassette/Wafer LOT 일치를 정의한다.

P5. 활성 Auto 및 결과 Data LOT 일관성
-------------------------------------

- StartAsync → StartSequenceAsync 활성 Auto preflight 위치를 정한다.
- Tact/Stats/Vision/CSV 생성 전에 등록 LOT을 검증한다.
- ActiveLot이 없으면 canonical LOT과 같은 통계 Session을 Open/Resume한다.
- ActiveLot이 있으면 canonical LOT과 불일치 시 차단한다.
- Cycle Stop/Alarm/재개 가능 Stop/정상 완료/재개 포기 종료별
  ActiveLot 수명과 Completed/Aborted 전환을 정의한다.
- Vision Request/Result, Input/Output CSV, TactTime의 LOT source를 표로 정리한다.
- 누락 fallback이 다른 새 LOT을 만들지 않게 한다.
- Legacy CycleRunAsync diff 0 보호 항목을 둔다.

P6. 맵핑 전/후 Target Resolver
-----------------------------

- 공통 이동 모드 enum과 결과 객체(Target, Source, Role, Slot, Reason)를 설계한다.
- 맵핑 전 역할별 FirstPosition + Pitch 공식을 단일 위치에 구현하도록 계획한다.
- Input2/Good2/NG 역할 매핑을 명시한다.
- 맵핑 전 과거 Mapping 배열 및 다른 레벨 fallback 금지를 명시한다.
- 맵핑 후 MaterialStateService의 현재 Wafer 저장 위치만 사용한다.
- Mapping 상태, Role/Slot/Wafer 위치 일치, legacy -1 sentinel,
  NaN/Infinity, Soft Limit 검증을 정의한다.
- 맵핑 후 빈 슬롯은 Fail-Closed로 확정한다.

P7. Input/Output 수동 이동 Sequence 연결
---------------------------------------

- Input의 현재 Page 직접 이동을 재검토하고, 동일 안전검사를 갖는
  단일 MoveSlot Sequence/Service 사용 계획을 작성한다.
- OutputCassetteMoveSlotSequence에 수동 명시 모드를 연결하되,
  기존 Auto/공정 기본 계산은 바꾸지 않는다.
- 수동 호출은 Fresh/Restart로 실행한다.
- 기존 ManualActionScope, 감지 센서, Feeder Avoid, 돌출 감시,
  MotionGuard, STOP/Cancellation을 유지한다.
- 완료 후 목표 도달 검증과 실패 알람/로그를 정의한다.

P8. WorkInfo UI의 모드/PREV/NEXT/더블클릭
---------------------------------------

- 두 Page에 “맵핑 전 / 맵핑 후” 선택 UI를 추가한다.
- 안전 기본값은 “맵핑 후”로 하고, 저장 위치가 없다고
  “맵핑 전”으로 자동 전환하지 않는 정책을 정한다.
- Role 변경 시 표시/선택 유지 정책을 정한다.
- 선택 Role/Slot/Mode/Target Source/Target 위치를 화면에 표시한다.
- PREV/NEXT의 최초 슬롯, 경계 슬롯, 역할 유지 규칙을 정한다.
- CassetteSlotView에는 DoubleClick 이벤트만 추가한다.
- 확인창 OK/Cancel 1회와 중복 클릭 차단을 설계한다.
- 기존 우클릭 MOVE는 같은 공통 경로로 유지한다.

P9. 로그/알람/운영 추적
----------------------

- LOT 등록/재등록/변경 차단/불일치/저장 결과 로그를 정의한다.
- 슬롯 이동 요청에 page, role, slot, mode, source, target,
  current position, result, cancel/interlock reason을 기록한다.
- 미등록/불일치/위치 누락/티칭 누락/범위 초과 알람 코드를 정의한다.
- 운영자가 다음 조치를 알 수 있는 한국어 메시지를 작성한다.

P10. 검증 순서
--------------

- 정적 검색
- diff/check
- Debug|x64 별도 OutDir Build
- Simulation 기능 검증
- Snapshot 저장/복구 검증
- 실장비 저속 검증
- Auto/Vision/CSV/Tact end-to-end 검증

순으로 검증 계획을 작성한다.

실장비 검증은 각 이동 전 목표 계산값을 운영자에게 표시하고,
First/Middle/Last 슬롯을 저속으로 확인한 뒤 전체 공정을 진행한다.

======================================================================
6. 계획서/체크리스트 산출물 형식
======================================================================

계획서는 다음 구조로 작성한다.

1. 분석 목적
2. 현재 구조와 호출 경로
3. 발견 문제 및 위험도
4. 확정 설계 원칙
5. 단계별 구현 계획(P0~P10)
6. 대상 파일/클래스/함수 표
7. 변경 금지/보존 항목
8. Simulation/실장비 검증 순서
9. 구현 전 사용자 확인 사항

체크리스트는 본 프롬프트의 ID를 유지하고,
각 항목에 결과/근거를 입력할 수 있는 TXT 형식으로 작성한다.

문서는 UTF-8 BOM, CRLF로 저장한다.
저장 위치는 Repository root가 아니라 아래 폴더를 사용한다.

D:\Source\CDT-320_New\cdt-320\codex-prompts

권장 파일명:

- cassette-lot-id-and-slot-move-plan.txt
- cassette-lot-id-and-slot-move-validation-checklist.txt

두 문서를 작성한 뒤:

- source code diff가 0인지 확인
- 문서 파일만 새로 생겼는지 확인
- 계획의 미확정 항목을 사용자에게 별도로 요약

하고 멈춘다.

코드는 구현하지 않는다.
